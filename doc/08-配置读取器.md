# 配置读取器 (ConfigReader)

## 模块概述

负责统一管理所有配置的读取和访问，包括 LLM 提供商配置、应用级配置、各模块参数配置、人格配置、定时任务配置。将配置读取逻辑从各模块中解耦，提供统一的配置访问入口。

## 配置来源

项目使用三种配置来源：

| 来源 | 文件 | 用途 |
|------|------|------|
| `appsettings.json` | `Resources/appsettings.json` | LLM提供商配置、应用级配置、模块参数配置、定时任务配置、当前激活人格 |
| 人格配置文件 | `Resources/Personalities/{人物名称}_person.json` | 人格定义（多个人格、指定LLM模型、提供商） |
| SQLite 数据库 | `Resources/Data/mochibot.db` | 用户运行时配置（UserConfig），走 DatabaseService |

> **设计原则**：
>
> - `appsettings.json` 存放**静态/启动时**配置（API密钥、默认参数、激活人格、定时任务等）
> - 人格配置文件存放**人格定义**（冷重启后生效）
> - SQLite 存放**运行时可变**配置（用户修改的名字、窗口位置等），通过 DatabaseService 读写，不重复造轮子

## 数据模型

| 模型 | 文件位置 | 说明 |
|------|---------|------|
| `ProviderConfig` | `Src/Core/Config/Models/ProviderConfig.cs` | LLM提供商配置（ApiKey、BaseUrl、ContextLimit） |
| `AppSettings` | `Src/Core/Config/Models/AppSettings.cs` | 应用级配置（用户名、激活人格、日志级别等） |
| `ModuleSettings` | `Src/Core/Config/Models/ModuleSettings.cs` | 各模块参数配置（记忆模块参数、内置任务参数、文本模板等） |
| `PersonalityConfig` | `Src/Core/Config/Models/PersonalityConfig.cs` | 人格配置根模型（含子人格列表） |
| `SubPersonality` | `Src/Core/Config/Models/PersonalityConfig.cs` | 子人格定义（含 ChatModels、VisionModels、FunctionModels） |
| `CronTask` | `Src/Core/Events/IEventDispatcher.cs` | 定时任务定义（Id、CronExpression、TaskType、Parameters） |

## 核心接口

```csharp
public interface IConfigReader
{
    // ========== Logger ==========
    ILogger Logger { get; }

    // ========== LLM提供商配置 ==========
    Dictionary<string, ProviderConfig> GetAllProviders();
    ProviderConfig? GetProvider(string providerName);
    IEnumerable<string> GetAvailableProviders();

    // ========== 应用级配置 ==========
    AppSettings GetAppSettings();

    // ========== 模块参数配置 ==========
    ModuleSettings GetModuleSettings();
    T GetModuleParam<T>(string paramName, T defaultValue);

    // ========== 人格配置 ==========
    PersonalityConfig? GetActivePersonality();
    PersonalityConfig? LoadPersonality(string personalityName);
    List<string> GetAvailablePersonalities();
    (List<string> chatModels, List<string>? visionModels) GetPersonalityModels(string subPersonalityName);

    // ========== 定时任务配置 ==========
    List<CronTask> GetCronTasks();

    // ========== 配置重载 ==========
    void Reload();
}
```

## 实现要点

### 1. 单例模式

ConfigReader 设计为单例，应用启动时调用 `Initialize()` 加载一次配置文件，后续通过 `ConfigReader.Instance` 访问。

### 2. 配置缓存与热重载

- 首次读取时解析 JSON 并缓存到内存
- 调用 `Reload()` 时重新读取文件并更新缓存
- 人格配置文件在首次访问时加载并缓存
- 如果配置文件不存在，`Reload()` 会自动生成包含默认配置的文件

### 3. 类型安全

- 所有配置参数通过强类型模型访问，避免魔法字符串
- 提供泛型方法 `GetModuleParam<T>()` 支持类型转换

### 4. 人物名称合法性检查

人格名称只允许中文、英文字母、数字、下划线，不能以数字开头，不区分大小写。

### 5. 上下文极限检查

`LlmClient` 在构建请求前，应通过 `ConfigReader` 获取当前使用模型的 `ContextLimit`，检查即将发送的 token 数是否超过限制，超过则需截断或压缩。

## Logger 日志系统

ConfigReader 统一管理 Logger 实例，所有模块必须通过 ConfigReader 获取 Logger 打印日志，禁止直接使用 `Console.WriteLine`。

| 方法 | 说明 |
|------|------|
| `Debug` | 调试日志 |
| `Info` | 普通信息 |
| `Warn` | 警告信息 |
| `Error` | 错误信息（可附带异常） |

日志输出支持控制台（带颜色区分级别）和文件（按日期分文件）两种方式，日志级别在 `AppSettings.LogLevel` 中配置。

## 人格配置文件规范

### 文件命名规则

```
Resources/Personalities/
├── xiaokeai_person.json        # 小可爱人格
├── linda_person.json           # 林妲人格
└── ...
```

- 文件名格式：`{人物名称}_person.json`
- 人物名称合法性检查：只允许中文、英文字母、数字、下划线，不能以数字开头，不区分大小写

### 模型配置格式

`chatModels` / `visionModels` / `FunctionModels` 中的每个元素格式为：`{提供商名称}/{模型名称}`

- `提供商名称` 对应 `appsettings.json` 中 `Providers` 节点下的 key
- `模型名称` 对应 LLM API 中的模型标识

### 故障转移（Fallback）机制

当模型列表中的第一个模型请求失败时，自动按顺序尝试下一个模型，直到成功或列表耗尽。触发条件包括 HTTP 5xx 错误、网络超时、rate limit、模型不可用等。

## 依赖关系

- **依赖**: `System.Text.Json`（.NET 内置，无需额外 NuGet 包）
- **被依赖**: `LlmClient`（获取提供商配置和 ContextLimit）、`Agent`（获取应用级配置和人格配置）、各模块（获取模块参数配置）、`EventDispatcher`（获取定时任务配置）
