## 🔴 功能失效

### 1. 长期记忆淘汰机制完全无效 ✅ 已修复

- **文件**: `Src/Agent/LongMemory.cs:52`
- **问题**: `EvictEntriesAsync(0, 90)` 生成 SQL `WHERE importance < 0 AND last_accessed_at < @CutoffDate`。由于 `importance` 始终 ≥ 0，条件永远为 false，淘汰 0 条记录。
- **影响**: `long_memory` 表无限增长。`AddEntryAsync` 在 `count >= maxEntries` 时触发淘汰，但淘汰是空操作；`RunMemoryMaintenanceAsync` 每次也调用 `EvictEntriesAsync(0, 30)`，同样无效。长期使用后 SQLite 查询性能持续下降。
- **修复**: `EvictEntriesAsync(0, 90)` → `EvictEntriesAsync(10, 90)`，importance < 10 且超过 90 天未访问的条目可被淘汰。

### 2. 配置热重载是死代码 ✅ 已修复

- **文件**: `Src/UI/SettingsWindow.xaml.cs:254`
- **问题**: `ConfigChanged` 事件的 `changedItems` 仅在 `UserName` 变更时添加 `"UserName"`。`Agent.OnConfigChanged` 检查 `"ProviderConfig"` / `"PersonalityConfig"` / `"MaxMessages"` 这三个 key 永远不会出现在列表中。
- **影响**: 用户在 SettingsWindow 修改 LLM 提供商 API Key、切换人格、调整记忆容量后点击保存，Agent 继续使用旧的 LlmClient、旧人格描述和旧记忆容量，直到应用重启。
- **修复**: 保存前快照旧值（AppSettings/Providers/ModuleSettings），保存后序列化比较，将实际变更的项加入 `changedItems`（ProviderConfig/PersonalityConfig/ModuleSettings/MaxMessages 等）。

### 3. 事件处理队列竞态丢失用户消息 ✅ 已修复

- **文件**: `Src/Agent/EventProcessingQueue.cs:77`
- **问题**: `ProcessQueueAsync` 的 while 循环在 `TryDequeue` 返回 false 后、`_processLock.Release()` 之前，如果有新事件入队，`TryStartProcessing` 因锁仍被持有而失败（`_processLock.Wait(0)` 返回 false）。锁释放后无人重新检查队列。
- **影响**: 用户发送的消息可能被永久卡在队列中，直到下一个外部事件（如 cron tick）触发 `TryStartProcessing`。在 cron 间隔较长时，用户会感觉消息"没发出去"。
- **修复**: 在 `_processLock.Release()` 之后重新检查 `_eventQueue.IsEmpty`，若非空则再次调用 `TryStartProcessing()`。

### 4. 空闲检测基于聊天时间而非用户活动 🟡 部分修复

- **文件**: `Src/Agent/AutoEventFilter.cs:58`
- **问题**: `_lastActivityTime` 仅在 `UserInput` 事件（用户发送聊天消息）时更新。鼠标、键盘活动不生成 `UserInput` 事件，因此 `_lastActivityTime` 实际记录的是"上次聊天时间"而非"上次活动时间"。
- **影响**: 用户持续使用鼠标键盘工作 3 小时但未发消息 → `EyeRest` cron（每 5 分钟）检查 `(DateTime.Now - _lastActivityTime).TotalMinutes >= 120` 为 true → 每 5 分钟触发一次 LLM "该休息了" 提醒，尽管用户一直在活跃工作。旧代码的 `BuiltinTaskHandler.RecordUserActivity()` 从 UI 层调用，已被删除。
- **部分修复**: `Update` → `UpdateAsync`，`TryHandleMurmur` → `TryHandleMurmurAsync`，修复同步阻塞异步方法的隐患。
- **待修复**: 需在 MainWindow 鼠标/键盘事件中调用活动记录，或新增全局 `UiInteraction` 事件来捕获桌面级用户活动。

### 5. 情绪日志功能完全失效 ✅ 已修复

- **文件**: `Src/Main.cs:42`
- **问题**: `MoodLogRepository` 从未在 `Main.cs` 中实例化。`MoodManager` 构造函数的 `moodLogRepository` 参数为 `null`，导致 `MoodManager.cs:66` 的 `_ = _moodLogRepository.LogMoodChangeAsync(...)` 永远不执行（null check 跳过）。
- **影响**: `mood_log` 表由 `DatabaseService.InitializeDatabase()` 创建但永远为空。用户查询情绪历史返回空列表。情绪追踪功能从重构提取 `MoodLogRepository` 后就断开了。
- **修复**: 在 `Main.cs` 的 `Initialize()` 中创建 `MoodLogRepository(databaseService)` 实例并传入 `MainAgent` 构造函数。

## 🟠 竞态 / 资源泄漏

### 6. 热重载替换 LlmClient 无同步保护

- **文件**: `Src/Agent/Agent.cs:170`
- **问题**: `OnConfigChanged` 在 UI 线程替换 `_chatLlmClient`（非 volatile 字段），而 `EventProcessingQueue` 线程可能正在 `ProcessWithLlmAsync` 中读取该字段。
- **影响**: 用户在 Agent 执行 LLM 调用期间保存设置 → `_chatLlmClient` 被替换 → 处理线程读到旧引用（ObjectDisposedException）或半构造对象。
- **修复建议**: 使用 `volatile` 关键字或 `lock` 保护 `_chatLlmClient` 的读写；或在 `OnConfigChanged` 中设置标志，让处理线程在安全点切换。

### 7. MoodChange 回调可能读错字段 ✅ 已修复

- **文件**: `Src/Agent/ActionExecutor.cs:272`
- **问题**: `HandleMoodChange` 读取 `action.Mood`，但 LLM 的格式指令中 `tool_call` 示例使用 `name` 字段。如果 LLM 遵循 `tool_call` 模式输出 `{type:"mood_change", name:"happy"}` 而非 `{type:"mood_change", mood:"happy"}`，则 `action.Mood` 为 null，`Enum.TryParse` 静默失败。
- **影响**: 宠物情绪永远停在 Neutral，无论 LLM 如何尝试切换情绪。
- **修复**: `HandleMoodChange` 中 `var moodStr = action.Mood ?? action.Name`，兼容两种字段。

### 8. RebuildMemories 不释放旧实例

- **文件**: `Src/Agent/MemoryCoordinator.cs:125`
- **问题**: `RebuildMemories` 直接替换 `ShortTermMemory` 和 `LongMemory` 引用，不释放旧实例。旧 `LongMemory` 持有 `LlmClient`（内部 HttpClient）和 `DatabaseService`（SQLite 连接）。
- **影响**: 用户多次修改 ProviderConfig → 多个旧实例的 HttpClient socket 和 SQLite 连接累积 → 最终 socket 耗尽导致 "Unable to connect" 错误。
- **修复建议**: 在替换前调用旧实例的 `Dispose()` 方法（需先为 `LongMemory`/`ShortTermMemory` 实现 `IDisposable`）。

### 9. Agent.Dispose 不退订事件

- **文件**: `Src/Agent/Agent.cs:523`
- **问题**: `Dispose()` 释放了 `MemoryCoordinator` 和 `EventProcessingQueue`，但未调用 `EventDispatcher.Unsubscribe` 退订 `_subscriptionIds` 中的 4 个订阅。
- **影响**: 关闭时 EventDispatcher 投递延迟的 SystemAuto 事件 → 触发 `TryStartProcessing` → `_processLock.Wait(0)` 访问已释放的 `SemaphoreSlim` → 抛出 `ObjectDisposedException`。
- **修复建议**: 在 `Dispose()` 中遍历 `_subscriptionIds` 调用 `_eventDispatcher.Unsubscribe()`。

### 10. SQLite 并发写入无保护

- **文件**: `Src/Agent/MemoryCoordinator.cs:42`
- **问题**: 维护定时器在 ThreadPool 线程执行 `DELETE`/`UPDATE`，而 `EventProcessingQueue` 线程执行 `INSERT`/`UPDATE`，两者操作同一 SQLite 文件。连接字符串含 `Pooling=False`，默认 busy timeout 为 0。
- **影响**: 定时器触发 `EvictEntriesAsync`（DELETE）同时主线程执行 `AddEntryAsync`（INSERT）→ 第二个写入者收到 `SqliteException (SQLITE_BUSY)` → 维护静默失败或记忆条目丢失。
- **修复建议**: 在连接字符串中添加 `Busy Timeout=5000`；或使用 WAL 模式（`Journal Mode=WAL`）允许并发读写。

## 🟡 行为回归

### 11. ShortTermMemory.Capacity setter 跨线程无同步

- **文件**: `Src/Agent/ShortTermMemory.cs:49`
- **问题**: `Capacity` setter（UI 线程通过 `OnConfigChanged` 调用）重新分配 `_buffer` 并重置 `_head`/`_count`，而 `AddMessage`（`EventProcessingQueue` 处理线程）并发写入 `_buffer`。
- **影响**: 用户保存设置 → UI 线程重建 buffer → 处理线程写入旧 buffer → 消息静默丢失。
- **修复建议**: 为 `_buffer` 操作添加 `lock`，或使用 `Interlocked.Exchange` 原子替换 buffer 引用。

### 12. EyeRest 无"触发一次"保护

- **文件**: `Src/Agent/AutoEventFilter.cs:160`
- **问题**: 旧 `BuiltinTaskHandler` 有 `_eyeRestFired` 标志，在单次空闲会话中只触发一次。`AutoEventFilter.ShouldProcessEvent` 仅检查经过时间，无等效标志。
- **影响**: 用户空闲 2+ 小时 → 每 5 分钟的 `eye_rest` cron 都通过时间检查 → 每 5 分钟触发一次 LLM 调用（24+ 次/空闲会话）。旧代码只触发一次直到用户恢复活动。
- **修复建议**: 添加 `_eyeRestFired` 标志，在 `ShouldProcessEvent` 中检查；用户活动时重置。

### 13. 总结循环可能无限触发

- **文件**: `Src/Agent/ShortTermMemory.cs:82`
- **问题**: `SummarizeAsync` 调用 `Clear()` 后 `AddMessage()` 重建缓冲区。如果 `SummaryReservedCount >= Capacity`，AddMessage 立即重新触发 `_summarizePending = true`。
- **影响**: `Capacity=10`, `SummaryReservedCount=10` 时：Clear → AddMessage(summary) → AddMessage×10 → count > capacity → `_summarizePending=true` → 下次检查再次总结，无限循环。每次循环消耗一次 LLM 调用。
- **修复建议**: 在 `SummarizeAsync` 开始时设 `_summarizePending = false`；或确保 `Capacity > SummaryReservedCount + 1`。

## 🔵 工程缺陷

### 14. ConfigReader.Reload 泄漏 JsonDocument

- **文件**: `Src/Core/Config/ConfigReader.cs:81`
- **问题**: `Reload()` 将 `_cachedDoc` 替换为新 `JsonDocument`，未释放旧实例。`JsonDocument` 持有从 `ArrayPool` 租借的字节数组。
- **影响**: 用户多次保存设置 → 多个 `JsonDocument` 实例泄漏 → GC 压力增大，内存占用持续增长。
- **修复建议**: 在 `_cachedDoc = JsonDocument.Parse(json)` 前添加 `_cachedDoc?.Dispose()`。

### 15. TrayIcon 右键菜单不自动消失

- **文件**: `Src/UI/TrayIcon.cs:155`
- **问题**: `ShowContextMenu` 调用 `TrackPopupMenu` 前未调用 `SetForegroundWindow`。这是 Win32 API 的文档化要求，缺失会导致菜单在点击其他窗口时不消失。
- **影响**: 用户右键托盘图标 → 菜单弹出 → 点击其他窗口或桌面 → 菜单保持可见且冻结，需按 Escape 或点击菜单本身才能关闭。
- **修复建议**: 在 `TrackPopupMenu` 前添加 `SetForegroundWindow(_hwnd)` 调用。
