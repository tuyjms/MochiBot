# 项目架构总览

## 项目简介

**AI女友 (catgirlwindow)** 是一个基于 .NET 10.0 WinForms 的桌面应用，通过 LLM（大语言模型）驱动，实现一个具有情感交互能力的虚拟伴侣。

## 技术栈

- **.NET**: 10.0-windows
- **UI 框架**: Windows Forms
- **LLM SDK**: OpenAI SDK v2.10.0
- **目标框架**: net9.0-windows

## 模块职责概览

- **Agent** (`catgirlwindow.Services`): 核心协调层，LLM与平台交互的唯一入口，协调所有子模块（不需要单元测试，见 `doc/00 - 写给viber的话.md` 的说明）
- **LlmClient** (`catgirlwindow.Services`): LLM API调用封装（统一管理密钥、重试、限流、故障转移）
- **ConfigReader** (`catgirlwindow.Services`): 配置读取器，统一管理 appsettings.json 和人格配置文件的读取，提供强类型配置访问
- **AgentMoodTracker** (`catgirlwindow.Services`): 管理AI女友情绪状态，根据事件自动切换
- **ShortTermMemory** (`catgirlwindow.Services`): 存储最近N条对话记录，构建LLM上下文
- **MidTermMemory** (`catgirlwindow.Services`): 事件级记忆，记录重要对话摘要（JSON存储）
- **LongTermMemory** (`catgirlwindow.Services`): 永久记忆，关键词索引+关系数据库（SQLite）
- **DatabaseService** (`catgirlwindow.Services`): 数据持久化（配置、聊天记录、情绪日志）
- **PromptFormatter** (`catgirlwindow.Services`): 通用模板格式化工具，各模块自己管理模板字符串
- **ToolService** (`catgirlwindow.Services`): 管理工具功能（计时器、夸奖、摸摸、天气）
- **AutoEventService** (`catgirlwindow.Services`): 管理定时触发的自动行为（通过Agent调度）
- **JsPluginLoader** (`catgirlwindow.Plugins`): 动态加载JS插件，扩展工具功能
- **CharacterRenderer** (`catgirlwindow.Renderer`): 角色动画渲染器，使用 GIF/PNG 图集实现动画，根据情绪切换动作

## 分层架构

项目分为四层，从上到下依次为：

1. **UI 层 (Form1)**: 只负责显示和用户输入，所有逻辑走 Agent 统一调度
2. **Agent 核心协调层**: 作为 LLM 与平台交互的唯一入口，内部协调 LlmClient、PromptFormatter、记忆模块（短/中/长）、工具服务、情绪管理器、插件加载器、数据库服务、角色动画渲染器
3. **数据模型层 (Models)**: ChatMessage、UserConfig、WeatherInfo、AgentMood
4. **基础设施层**: 插件系统 (Plugins)、渲染器 (Renderer)、配置文件 (appsettings.json)

## 核心架构原则

1. **Agent 是唯一入口**: Form1 不再直接调用 LlmClient/Memory/ToolService 等，全部通过 Agent 统一调度
2. **两种 LLM 模式**: 对话模式（LLM扮演女友人格）和函数模式（LLM作为纯函数，保证稳定性）
3. **AutoEventService 只负责定时**: 自动事件触发后，由 Agent 的 ProcessAutoEventAsync() 统一处理
4. **面向接口编程**: 所有模块通过接口交互，便于单元测试和模块替换

## feature

- 向量数据库+关系数据库用于保存重大事件（向量数据库的意义只在于模糊语义匹配关键词，实际用关键词去关系数据库查找，保证准确的同时不失语义匹配的优势）
- GIF/PNG 图集驱动的角色动画
- 对接QQ平台，让你躺着也能聊

### 工具提示词动态加载

工具描述按三层结构动态注入 LLM 的 system prompt：

#### 第一层 — 基础工具（直接注入）

- timer、compliment、pet、weather 等内置工具
- 它们的 ToolDefinition 直接注入 system prompt，LLM 可直接调用

#### 第二层 — 插件工具 + MCP 服务器工具（通过 list_plugins 间接获取）

- 新增一个基础工具 `list_plugins`，描述为"列出所有已加载的JS插件和MCP服务器工具及其描述"
- LLM 需要先调用 `list_plugins` 获取插件/MCP工具列表，再根据返回的描述决定是否调用
- JS 插件调用通过 `plugin_call` action 执行
- MCP 服务器工具调用通过 `mcp_call` action 执行
- 两者使用完全相同的动态加载机制，LLM 无需区分底层实现

#### 第三层 — 心情附加工具（动态注入）

- 根据当前情绪状态，在基础工具描述里动态添加附加工具
- 例如：情绪为 Sad 时，注入 `hug` 工具（拥抱安慰）；情绪为 Happy 时，注入 `dance` 工具（一起跳舞）
- 这些附加工具只在特定情绪下可见，情绪切换后自动移除

```csharp
// Agent 构建工具描述时的伪代码
var toolDescriptions = new List<string>();

// 第一层：基础工具
foreach (var tool in _toolService.GetToolDefinitions())
    toolDescriptions.Add($"{tool.Name}: {tool.Description}");

// 第二层：插件/MCP查询工具（LLM需要主动调用 list_plugins 获取）
toolDescriptions.Add("list_plugins: 列出所有已加载的JS插件和MCP服务器工具及其描述");

// 第三层：心情附加工具
var moodTools = _toolService.GetMoodBasedTools(_moodTracker.CurrentMood);
foreach (var tool in moodTools)
    toolDescriptions.Add($"{tool.Name}: {tool.Description} (当前心情可用)");
```

#### list_plugins 返回格式

```json
{
  "plugins": [
    {"type": "js_plugin", "name": "weather", "description": "查询天气预报", "parameters": {"city": "string"}},
    {"type": "js_plugin", "name": "timer", "description": "设置倒计时", "parameters": {"seconds": "number"}}
  ],
  "mcp_tools": [
    {"type": "mcp_tool", "name": "search_products", "description": "搜索电商商品（电商MCP）", "parameters": {"keyword": "string", "page": "number"}},
    {"type": "mcp_tool", "name": "get_news", "description": "获取最新新闻（新闻MCP）", "parameters": {"category": "string"}}
  ]
}
```

#### 调用方式

```json
{
  "reply": "我帮你查一下最新的科技新闻～",
  "actions": [
    {"type": "mcp_call", "server": "news_mcp", "name": "get_news", "parameters": {"category": "technology"}}
  ]
}
```
