# 项目架构总览

## 项目简介

**LLM桌宠 (Mochi)** 是一个基于 .NET 10.0 WinForms 的桌面应用，通过 LLM（大语言模型）驱动，实现一个具有情感交互能力的虚拟宠物。

## 技术栈

- **.NET**: 10.0-windows
- **UI 框架**: Windows Forms
- **LLM SDK**: OpenAI SDK v2.10.0
- **目标框架**: net9.0-windows

## 模块职责概览

### 核心层 (Src/Core)

- **配置管理器** (`Src/Core/Config/`): 统一管理 appsettings.json 和人格配置文件的读取，提供强类型配置访问
- **数据库业务层** (`Src/Core/Database/`): 数据持久化（配置、聊天记录、情绪日志）
- **事件调度器** (`Src/Core/Events/`): 统一的事件分发中心，所有事件（用户输入、系统自动事件、工具结果等）都通过事件调度器分发
- **事件定义** (`Src/Core/Events/EventTypes.cs`): 事件基础类型枚举、事件模型定义
- **心情枚举** (`Src/Core/Models/AgentMood.cs`): AI桌宠情绪状态枚举

### Agent层 (Src/Agent)

- **Agent核心协调层** (`Src/Agent/Agent.cs`): 系统的"大脑"，协调所有子模块，处理事件调度器分发的事件
- **心情记录器** (`Src/Agent/AgentMoodTracker.cs`): 集成到Agent中，管理AI桌宠情绪状态
- **短期记忆** (`Src/Agent/ShortTermMemory.cs`): 集成到Agent中，存储最近N条对话记录
- **长期记忆** (`Src/Agent/LongMemory.cs`): 中期记忆和长期记忆合并，统一管理重要信息的存储和检索
- **Prompt格式化器** (`Src/Agent/PromptFormatter.cs`): 通用模板格式化工具

### 服务层 (Src/Services)

- **工具管理器** (`Src/Services/ToolManager.cs`): 统一调度所有工具（基础工具、心情特色工具、MCP工具、DLLMOD插件）
- **LLM客户端** (`Src/Services/LlmClient.cs`): LLM API调用封装
- **DLLMOD插件模块** (`Src/Services/DllModModule/`): 动态加载DLL作为插件
- **MCP服务管理** (`Src/Services/McpModule/`): 管理MCP服务器工具

### UI层 (Src/UI)

- **主窗口** (`Src/UI/Form1.cs`): 只负责显示和用户输入，所有逻辑通过事件调度器走 Agent 统一调度

### 渲染层 (Src/Renderer)

- **角色动画渲染器接口** (`Src/Renderer/ICharacterRenderer.cs`): 角色动画渲染接口

### 路由层 (Src/Router)

- 预留的多平台支持模块（QQ平台等）

## 事件流向（核心架构变更）

```
用户交互 / 系统自动事件
        │
        ▼
  事件调度器 (EventDispatcher)
        │
        ├── 事件分类打包（EventCategory + EventType + Info）
        │
        ▼
  Agent 核心协调层
        │
        ├── 消息预处理 / 情绪判断 / 短期记忆记录
        │
        ▼
  LLM 处理（对话模式 / 函数模式）
        │
        ▼
  Agent 解析 LLM 响应（actions）
        │
        ▼
  工具管理器 (ToolManager)
        │
        ├── 基础工具（timer / compliment / pet）
        ├── 心情特色工具（hug / dance / tuck_in / cuddle / calm_down）
        ├── MCP工具（通过MCP服务管理）
        └── DLLMOD插件（通过DLLMOD加载器）
              │
              ▼
        结果返回 Agent → 由工具把消息回复用户
```

## 核心架构原则

1. **事件驱动架构**: 所有交互（用户输入、系统事件、工具结果）都通过事件调度器分发
2. **Agent 是唯一入口**: Agent 处理所有事件，协调各模块
3. **工具管理器统一调度**: 基础工具、心情工具、MCP工具、DLLMOD插件统一由 ToolManager 管理
