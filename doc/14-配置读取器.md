# 配置读取器 (ConfigReader)

## 模块概述

负责统一管理所有配置的读取和访问，包括 LLM 提供商配置、应用级配置、各模块参数配置、人格配置。将配置读取逻辑从各模块中解耦，提供统一的配置访问入口。

## 配置来源

项目使用三种配置来源：

| 来源 | 文件 | 用途 |
| `appsettings.json` | `appsettings.json` | LLM提供商配置、应用级配置、模块参数配置、当前激活人格 |
| 人格配置文件 | `Resources/Personalities/{人物名称}_person.json` | 人格定义（多个人格、指定LLM模型） |
| SQLite 数据库 | `Resources/Data/mochibot.db` | 用户运行时配置（UserConfig），走 DatabaseService |

> **设计原则**：
>
> - `appsettings.json` 存放**静态/启动时**配置（API密钥、默认参数、激活人格等）
> - 人格配置文件存放**人格定义**（冷重启后生效）
> - SQLite 存放**运行时可变**配置（用户修改的名字、窗口位置等），通过 DatabaseService 读写，不重复造轮子

## 数据模型

### 配置模型

```csharp
/// <summary>
/// 应用配置根模型
/// </summary>
public class AppConfig
{
    /// <summary>LLM提供商配置字典</summary>
    public Dictionary<string, ProviderConfig> Providers { get; set; } = new();

    /// <summary>应用级配置</summary>
    public AppSettings Settings { get; set; } = new();
}

/// <summary>
/// LLM提供商配置
/// </summary>
public class ProviderConfig
{
    /// <summary>API密钥</summary>
    public string ApiKey { get; set; } = string.Empty;

    /// <summary>API基础地址</summary>
    public string BaseUrl { get; set; } = string.Empty;

    /// <summary>上下文极限（token数），超过此值需截断或压缩，防止调用时溢出</summary>
    public int ContextLimit { get; set; } = 4096;
}

/// <summary>
/// 应用级配置
/// </summary>
public class AppSettings
{
    /// <summary>默认使用的提供商名称</summary>
    public string DefaultProvider { get; set; } = "LocalLMStudio";

    /// <summary>对话模式使用的模型名称（默认值，人格配置可覆盖）</summary>
    public string ChatModel { get; set; } = "default";

    /// <summary>函数模式使用的模型名称（可指定更便宜的模型）</summary>
    public string FunctionModel { get; set; } = "default";

    /// <summary>当前激活的人格名称（对应 Resources/Personalities/ 下的 {名称}_person.json）</summary>
    public string ActivePersonality { get; set; } = "default";

    /// <summary>是否启用LLM结构化响应解析</summary>
    public bool EnableStructuredResponse { get; set; } = true;

    /// <summary>单次LLM响应最大执行动作数</summary>
    public int MaxActionsPerResponse { get; set; } = 5;

    /// <summary>对话时是否允许LLM主动录入中期记忆</summary>
    public bool EnableMidTermMemoryOnChat { get; set; } = true;

    /// <summary>对话时是否检索长期记忆注入上下文</summary>
    public bool EnableLongTermRecall { get; set; } = true;
}
```

### 人格配置模型

人格配置使用独立的 JSON 文件存储，文件名格式为 `{人物名称}_person.json`，存放在 `Resources/Personalities/` 目录下。

```csharp
/// <summary>
/// 人格配置根模型（对应 {人物名称}_person.json）
/// </summary>
public class PersonalityConfig
{
    /// <summary>人物名称（仅允许中文、英文、数字、下划线，且不能以数字开头）</summary>
    public string Name { get; set; } = string.Empty;

    /// <summary>人物描述/背景故事</summary>
    public string Description { get; set; } = string.Empty;

    /// <summary>子人格列表</summary>
    public List<SubPersonality> Personalities { get; set; } = new();
}

/// <summary>
/// 子人格定义
/// </summary>
public class SubPersonality
{
    /// <summary>子人格名称（如：温柔、毒舌、活泼）</summary>
    public string Name { get; set; } = string.Empty;

    /// <summary>子人格描述/行为规则</summary>
    public string Description { get; set; } = string.Empty;

    /// <summary>
    /// 对话主力LLM模型列表（按优先级排序，支持故障转移）
    /// 格式："{提供商名称}/{模型名称}"
    /// 示例：["LocalLMStudio/qwen2.5-7b", "OpenAI/gpt-4o-mini"]
    /// 当第一个模型请求失败时，自动 fallback 到下一个模型
    /// </summary>
    public List<string> ChatModels { get; set; } = new();

    /// <summary>
    /// 图转文字LLM模型列表（可选，按优先级排序，支持故障转移）
    /// 格式同上，为空时使用 ChatModels 的第一个
    /// </summary>
    public List<string>? VisionModels { get; set; }
}
```

## Logger 日志系统

ConfigReader 统一管理 Logger 实例，所有模块必须通过 ConfigReader 获取 Logger 打印日志，禁止直接使用 `Console.WriteLine`。

### Logger 接口

```csharp
/// <summary>
/// 日志记录器接口
/// </summary>
public interface ILogger
{
    void Debug(string message);
    void Info(string message);
    void Warn(string message);
    void Error(string message, Exception? ex = null);
}
```

### 使用方式

```csharp
// 任意模块中通过 ConfigReader 获取 Logger
ConfigReader.Instance.Logger.Info("模块初始化完成");
ConfigReader.Instance.Logger.Warn("配置项 {0} 使用默认值", paramName);
ConfigReader.Instance.Logger.Error("LLM 请求失败", exception);
```

### 日志输出

- **控制台输出**：带颜色区分日志级别（Debug=灰、Info=白、Warn=黄、Error=红）
- **文件输出**：写入 `Resources/Logs/` 目录，按日期分文件（如 `2026-05-05.log`）
- **日志格式**：`[2026-05-05 17:00:00] [INFO] [ModuleName] 消息内容`

### Logger 配置

日志级别在 `appsettings.json` 的 `AppSettings` 中配置：

```json
{
  "AppSettings": {
    "LogLevel": "Info",
    "LogToFile": true,
    "LogToConsole": true
  }
}
```

## 核心接口

```csharp
/// <summary>
/// 配置读取器接口
/// </summary>
public interface IConfigReader
{
    // ========== Logger ==========

    /// <summary>获取日志记录器实例</summary>
    ILogger Logger { get; }


    // ========== LLM提供商配置 ==========

    /// <summary>获取所有LLM提供商配置</summary>
    Dictionary<string, ProviderConfig> GetAllProviders();

    /// <summary>获取指定提供商的配置</summary>
    ProviderConfig? GetProvider(string providerName);

    /// <summary>获取所有可用的提供商名称列表</summary>
    IEnumerable<string> GetAvailableProviders();


    // ========== 应用级配置 ==========

    /// <summary>获取应用级配置</summary>
    AppSettings GetAppSettings();


    // ========== 模块参数配置 ==========

    /// <summary>获取模块参数配置</summary>
    ModuleSettings GetModuleSettings();

    /// <summary>获取指定模块的单个参数值</summary>
    T GetModuleParam<T>(string paramName, T defaultValue);


    // ========== 人格配置 ==========

    /// <summary>获取当前激活的人格配置</summary>
    PersonalityConfig? GetActivePersonality();

    /// <summary>根据人物名称加载人格配置</summary>
    PersonalityConfig? LoadPersonality(string personalityName);

    /// <summary>获取所有可用的人格名称列表</summary>
    List<string> GetAvailablePersonalities();

    /// <summary>获取指定子人格的LLM模型配置</summary>
    /// <param name="subPersonalityName">子人格名称</param>
    /// <returns>(chatModels, visionModels) 元组，visionModels 可能为 null</returns>
    (List<string> chatModels, List<string>? visionModels) GetPersonalityModels(string subPersonalityName);


    // ========== 配置重载 ==========

    /// <summary>重新加载配置文件（热更新）</summary>
    void Reload();
}
```

## 人格配置文件规范

### 文件命名规则

```txt
Resources/Personalities/
├── xiaokeai_person.json        # 小可爱人格
├── linda_person.json           # 林妲人格
└── ...
```

- 文件名格式：`{人物名称}_person.json`
- 人物名称合法性检查：
  - 只允许中文、英文字母、数字、下划线
  - 不能以数字开头
  - 不能为空
  - 不区分大小写（统一转为小写存储）

### 人格配置文件示例

```json
{
  "name": "小可爱",
  "description": "一个温柔可爱的AI女友，喜欢撒娇和关心人",
  "personalities": [
    {
      "name": "温柔",
      "description": "温柔体贴，说话轻声细语，总是为对方着想",
      "chatModels": ["LocalLMStudio/qwen2.5-7b", "OpenAI/gpt-4o-mini"],
      "visionModels": ["OpenAI/gpt-4o-mini"]
    },
    {
      "name": "毒舌",
      "description": "嘴上不饶人，但内心其实很关心对方",
      "chatModels": ["LocalLMStudio/qwen2.5-7b"]
    },
    {
      "name": "活泼",
      "description": "元气满满，充满活力，喜欢开玩笑",
      "chatModels": ["DeepSeek/deepseek-chat", "OpenAI/gpt-4o-mini"]
    }
  ]
}
```

### 模型配置格式

`chatModels` 和 `visionModels` 中的每个元素格式为：`{提供商名称}/{模型名称}`

- `提供商名称` 对应 `appsettings.json` 中 `Providers` 节点下的 key
- `模型名称` 对应 LLM API 中的模型标识

示例：

- `LocalLMStudio/qwen2.5-7b` → 使用 LocalLMStudio 提供商，模型为 qwen2.5-7b
- `OpenAI/gpt-4o-mini` → 使用 OpenAI 提供商，模型为 gpt-4o-mini
- `DeepSeek/deepseek-chat` → 使用 DeepSeek 提供商，模型为 deepseek-chat

### 故障转移（Fallback）机制

当 `chatModels` 列表中的第一个模型请求失败时，自动按顺序尝试下一个模型，直到成功或列表耗尽：

请求 → chatModels[0] → 失败 → chatModels[1] → 失败 → chatModels[2] → 成功 ✓

故障转移触发条件：

- API 返回 HTTP 5xx 错误
- 网络超时（超过配置的超时时间）
- API 返回 rate limit 错误
- 模型不可用（如上下文溢出、模型已下线）

## 实现要点

### 1. 单例模式

ConfigReader 设计为单例，应用启动时加载一次配置文件，后续通过静态方法访问：

```csharp
// 应用启动时初始化
ConfigReader.Initialize("appsettings.json");

// 任意位置访问配置
var providers = ConfigReader.Instance.GetAllProviders();
var settings = ConfigReader.Instance.GetAppSettings();

// 获取当前激活的人格配置
var personality = ConfigReader.Instance.GetActivePersonality();
var (chatModels, visionModels) = ConfigReader.Instance.GetPersonalityModels("温柔");
```

### 2. 配置缓存与热重载

- 首次读取时解析 JSON 并缓存到内存
- 调用 `Reload()` 时重新读取文件并更新缓存
- 人格配置文件在首次访问时加载并缓存

### 3. 类型安全

- 所有配置参数通过强类型模型访问，避免魔法字符串
- 提供泛型方法 `GetModuleParam<T>()` 支持类型转换

### 4. 向后兼容

- `LlmClient` 原有的 `LoadProviders()` 方法可以改为调用 `ConfigReader` 实现
- 保持 `LlmClient` 的公开接口不变，内部实现迁移

### 5. 人物名称合法性检查

```csharp
private static bool IsValidPersonalityName(string name)
{
    if (string.IsNullOrWhiteSpace(name))
        return false;

    // 不能以数字开头
    if (char.IsDigit(name[0]))
        return false;

    // 只允许中文、英文字母、数字、下划线
    return Regex.IsMatch(name, @"^[\u4e00-\u9fa5a-zA-Z0-9_]+$");
}
```

### 6. 上下文极限检查

`LlmClient` 在构建请求前，应通过 `ConfigReader` 获取当前使用模型的 `ContextLimit`，检查即将发送的 token 数是否超过限制。如果超过，需先进行截断或压缩：

```csharp
// LlmClient 中的上下文检查逻辑
var provider = _configReader.GetProvider(providerName);
if (provider != null && estimatedTokens > provider.ContextLimit)
{
    // 超过上下文极限，需要截断或压缩
    messages = TruncateMessages(messages, provider.ContextLimit);
}
```

## 事件流

1. 应用启动时 `Program.Main()` 调用 `ConfigReader.Initialize("appsettings.json")`
2. ConfigReader 读取并解析 `appsettings.json`，构建 `AppConfig` 和 `ModuleSettings` 对象
3. 根据 `AppSettings.ActivePersonality` 加载对应的人格配置文件 `{名称}_person.json`
4. 各模块通过 `ConfigReader.Instance` 获取所需配置
5. Agent 启动时通过 `GetActivePersonality()` 获取人格配置，初始化 LLM 客户端
6. LlmClient 发送请求前检查 `ContextLimit`，防止上下文溢出
7. 运行时若配置文件变更，调用 `Reload()` 更新缓存
8. 用户运行时配置（UserConfig）仍通过 `DatabaseService` 读写 SQLite

## 迁移计划

### 第一步：创建 ConfigReader 模块

- 创建 `Services/ConfigReader.cs`（实现类）
- 创建 `Services/IConfigReader.cs`（接口）
- 将 `LlmClient` 中的 `LoadProviders()` 逻辑迁移到 ConfigReader

### 第二步：更新 LlmClient

- `LlmClient` 构造函数改为接收 `IConfigReader` 依赖注入
- 移除 `LlmClient` 中的 `LoadProviders()` 私有方法
- 在发送请求前添加 `ContextLimit` 检查逻辑

### 第三步：各模块接入

- 各模块通过 `IConfigReader` 获取模块参数配置
- 移除各模块中的硬编码默认值

### 第四步：更新 appsettings.json

- 添加 `AppSettings` 和 `ModuleSettings` 节点
- 在 `AppSettings` 中添加 `ActivePersonality` 字段
- 为每个提供商添加 `ContextLimit` 字段
- 保留原有的 `Providers` 节点

### 第五步：创建人格配置文件

- 创建 `Resources/Personalities/` 目录
- 创建默认人格配置文件（如 `xiaokeai_person.json`）

## 依赖关系

- **依赖**:
  - `System.Text.Json`（.NET 内置，无需额外 NuGet 包）
  - `DatabaseService`（04-数据库业务层）— 用户运行时配置（UserConfig）通过 DatabaseService 读写 SQLite，ConfigReader 不重复造轮子
- **被依赖**: `LlmClient`（获取提供商配置和 ContextLimit）、`Agent`（获取应用级配置和人格配置）、各模块（获取模块参数配置）

## 与现有模块的关系

ConfigReader 负责读取 appsettings.json 和人格配置文件，提供统一的配置访问入口。

- LlmClient 通过 ConfigReader 获取提供商配置（含 ContextLimit），并在发送请求前检查上下文极限
- Agent 通过 ConfigReader 获取应用级配置和当前激活的人格配置
- 各模块通过 ConfigReader 获取模块参数配置

DatabaseService 负责用户运行时配置（UserConfig）的读写，通过 SQLite 管理。ConfigReader 与 DatabaseService 职责分离，不重复造轮子。

> **注意**：ConfigReader 只负责读取 `appsettings.json` 和人格配置文件中的静态配置。用户运行时配置（如名字、性格、窗口位置等）仍由 `DatabaseService` 通过 SQLite 管理，两者职责分离。
