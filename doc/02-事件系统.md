# 事件系统 (Event System)

## 模块概述

事件系统是项目的**核心骨架**，所有交互（用户输入、系统自动事件、工具结果等）都通过事件调度器统一分发。事件系统解耦了事件源和事件处理器，使得架构更加清晰和可扩展。

## 事件流向

### 1. 用户发送消息

```
用户输入文本 → Form1
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: UserInput,
        EventType: "chat",
        Info: "用户输入的内容"
      ))
    → Agent 订阅了 UserInput 事件
    → Agent.HandleAsync(event)
    → 短期记忆.AddMessage("user", event.Info)
    → LLM 处理（对话模式）
    → Agent 解析 actions
    → ToolService 执行工具
    → Agent 回复用户
```

### 2. 用户摸摸角色

```
用户点击"摸摸她" → Form1
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: UiInteraction,
        EventType: "pet",
        Info: ""
      ))
    → Agent 订阅了 UiInteraction 事件
    → Agent.HandleAsync(event)
    → 判断 event.EventType == "pet"
    → 基本反应：情绪切换为 Touched
    → 概率触发 LLM 处理
    → 如果触发：LLM 生成回复 + actions
    → ToolService 执行工具
    → 回复用户
```

### 3. 系统自动事件

```
EventDispatcher 定时器触发（Cron 任务匹配）
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: SystemAuto,
        EventType: "murmur" / "eye_rest" / "late_night",
        Info: "附加信息（可选）"
      ))
    → Agent 订阅了 SystemAuto 事件
    → Agent.HandleAsync(event)
    → 根据 EventType 构建对应 Prompt
    → LLM 处理（对话模式）
    → Agent 解析 actions
    → ToolService 执行工具
    → 回复用户
```

### 4. 工具执行结果

```
ToolService 执行工具完成
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: ToolResult,
        EventType: "timer_complete" / "weather_result",
        Info: "工具执行结果 JSON"
      ))
    → Agent 订阅了 ToolResult 事件
    → Agent 处理结果
```

## 事件调度器实现要点

### 1. 异步事件处理

事件调度器使用异步方式处理事件，避免阻塞事件发布者。

### 2. 事件队列

Agent 内部维护一个事件队列（`ConcurrentQueue<EventData>`），收到事件先入队不立即处理。Agent 状态机在 Idle 时从队列取出事件处理。队列设最大长度，满时丢弃最旧事件。（详见 `doc/03-Agent核心协调层.md`）

### 3. 事件日志

所有事件都会记录到日志中，便于调试和追踪。

## 事件类型对照表

> 事件分类定义在 `Src/EventModels/EventTypes.cs`，共 9 类。

| EventCategory | 触发示例 | 说明 |
|--------------|---------|------|
| UserInput | "chat" | 用户发送聊天消息 |
| UiInteraction | "pet", "hug" | 用户点击交互按钮 |
| SystemAuto | "murmur", "eye_rest", "late_night" | 系统定时触发的事件 |
| MoodChange | "happy", "sad", "sleepy" | 情绪状态变化 |
| ToolResult | "timer_complete" | 工具执行完成 |
| Plugin | "plugin_loaded" | 插件事件 |
| Mcp | "mcp_tool_call" | MCP 服务事件 |
| ConfigUpdate | "update_request" | 配置更新请求（UI → ConfigReader） |
| ConfigChanged | "config_reloaded" | 配置已变更（ConfigReader → 各模块，热重载） |

## 依赖关系

- **依赖**: 无（独立运行，只依赖基础类型）
- **被依赖**: `Form1`（发布事件）、`Agent`（订阅事件）、`BuiltinTaskHandler`（定时任务触发系统事件）

## 单元测试要求

| 测试用例 | 预期结果 |
|---------|----------|
| 发布事件后处理器被调用 | PublishAsync 后订阅的处理器被执行 |
| 取消订阅后不再处理 | Unsubscribe 后处理器不再被调用 |
| 多个处理器订阅同一事件 | 所有处理器都被调用 |
| 事件附带信息正确传递 | 处理器接收到的 Info 与发布时一致 |
| 事件队列满时丢弃旧事件 | 超过队列容量时丢弃最旧事件 |
| 启动/停止调度器 | Start/Stop 后状态正确 |
