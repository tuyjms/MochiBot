# 事件系统 (Event System)

## 模块概述

事件系统是项目的**核心骨架**，所有交互（用户输入、系统自动事件、工具结果等）都通过事件调度器统一分发。事件系统解耦了事件源和事件处理器，使得架构更加清晰和可扩展。

## 事件定义

### 事件基础类型枚举

```csharp
/// <summary>
/// 事件基础类型枚举
/// </summary>
public enum EventCategory
{
    /// <summary>用户输入消息</summary>
    UserMessage,
    /// <summary>用户交互动作（摸摸、抱抱等）</summary>
    UserInteraction,
    /// <summary>系统自动事件（定时触发）</summary>
    SystemAuto,
    /// <summary>情绪变化事件</summary>
    MoodChange,
    /// <summary>工具执行结果</summary>
    ToolResult,
    /// <summary>系统通知</summary>
    SystemNotification
}
```

### 事件模型

```csharp
/// <summary>
/// 事件定义
/// </summary>
public class GameEvent
{
    /// <summary>事件基础类型（枚举）</summary>
    public EventCategory Category { get; set; }

    /// <summary>具体事件类型（字符串，如 "pet", "compliment", "murmur", "eye_rest", "late_night"）</summary>
    public string EventType { get; set; } = string.Empty;

    /// <summary>事件附带信息（JSON字符串或纯文本）</summary>
    public string Info { get; set; } = string.Empty;

    /// <summary>事件来源</summary>
    public string Source { get; set; } = string.Empty;

    /// <summary>事件发生时间</summary>
    public DateTime Timestamp { get; set; } = DateTime.Now;
}
```

## 事件调度器接口

```csharp
/// <summary>
/// 事件调度器接口
/// </summary>
public interface IEventDispatcher
{
    /// <summary>发布事件（异步）</summary>
    /// <param name="gameEvent">要发布的事件</param>
    Task PublishAsync(GameEvent gameEvent);

    /// <summary>订阅事件</summary>
    /// <param name="category">事件类型</param>
    /// <param name="handler">事件处理器</param>
    void Subscribe(EventCategory category, Func<GameEvent, Task> handler);

    /// <summary>取消订阅事件</summary>
    /// <param name="category">事件类型</param>
    /// <param name="handler">事件处理器</param>
    void Unsubscribe(EventCategory category, Func<GameEvent, Task> handler);

    /// <summary>启动事件调度器</summary>
    void Start();

    /// <summary>停止事件调度器</summary>
    void Stop();
}
```

## 事件处理器基类

```csharp
/// <summary>
/// 事件处理器基类
/// </summary>
public abstract class EventHandlerBase
{
    /// <summary>处理器名称</summary>
    public abstract string HandlerName { get; }

    /// <summary>处理事件</summary>
    /// <param name="gameEvent">事件</param>
    public abstract Task HandleAsync(GameEvent gameEvent);

    /// <summary>获取此处理器感兴趣的事件类型列表</summary>
    public abstract List<EventCategory> GetInterestedCategories();
}
```

## 事件流向

### 1. 用户发送消息

```
用户输入文本 → Form1
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: UserMessage,
        EventType: "chat",
        Info: "用户输入的内容"
      ))
    → Agent 订阅了 UserMessage 事件
    → Agent.HandleAsync(event)
    → 短期记忆.AddMessage("user", event.Info)
    → LLM 处理（对话模式）
    → Agent 解析 actions
    → ToolManager 执行工具
    → Agent 回复用户
```

### 2. 用户摸摸角色

```
用户点击"摸摸她" → Form1
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: UserInteraction,
        EventType: "pet",
        Info: ""
      ))
    → Agent 订阅了 UserInteraction 事件
    → Agent.HandleAsync(event)
    → 判断 event.EventType == "pet"
    → 基本反应：情绪切换为 Touched
    → 概率触发 LLM 处理
    → 如果触发：LLM 生成回复 + actions
    → ToolManager 执行工具
    → 回复用户
```

### 3. 系统自动事件（原 AutoEventService）

```
AutoEventService 定时器触发
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: SystemAuto,
        EventType: "murmur" / "eye_rest" / "late_night",
        Info: "附加信息（可选）"
      ))
    → Agent 订阅了 SystemAuto 事件
    → Agent.HandleAsync(event)
    → 根据 EventType 构建对应 Prompt
    → LLM 处理（对话模式）
    → Agent 解析 actions
    → ToolManager 执行工具
    → 回复用户
```

### 4. 工具执行结果

```
ToolManager 执行工具完成
    → EventDispatcher.PublishAsync(new GameEvent(
        Category: ToolResult,
        EventType: "timer_complete" / "weather_result",
        Info: "工具执行结果 JSON"
      ))
    → Agent 订阅了 ToolResult 事件
    → Agent 处理结果
```

## 事件调度器实现要点

### 1. 异步事件处理

事件调度器使用异步方式处理事件，避免阻塞事件发布者。

### 2. 事件队列

事件调度器内部维护一个事件队列，支持事件的异步处理和优先级调度。队列满时丢弃最旧事件。

### 3. 事件日志

所有事件都会记录到日志中，便于调试和追踪。

## 事件类型对照表

| EventCategory | EventType 示例 | 说明 |
|--------------|----------------|------|
| UserMessage | "chat" | 用户发送聊天消息 |
| UserInteraction | "pet", "hug", "compliment" | 用户点击交互按钮 |
| SystemAuto | "murmur", "eye_rest", "late_night" | 系统定时触发的事件 |
| MoodChange | "happy", "sad", "sleepy" | 情绪状态变化 |
| ToolResult | "timer_complete", "weather_result" | 工具执行完成 |
| SystemNotification | "config_reloaded", "plugin_loaded" | 系统状态通知 |

## 依赖关系

- **依赖**: 无（独立运行，只依赖基础类型）
- **被依赖**: `Form1`（发布事件）、`Agent`（订阅事件）、`AutoEventService`（发布系统事件）

## 单元测试要求

| 测试用例 | 预期结果 |
|---------|----------|
| 发布事件后处理器被调用 | PublishAsync 后订阅的处理器被执行 |
| 取消订阅后不再处理 | Unsubscribe 后处理器不再被调用 |
| 多个处理器订阅同一事件 | 所有处理器都被调用 |
| 事件附带信息正确传递 | 处理器接收到的 Info 与发布时一致 |
| 事件队列满时丢弃旧事件 | 超过队列容量时丢弃最旧事件 |
| 启动/停止调度器 | Start/Stop 后状态正确 |
