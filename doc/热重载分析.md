# 配置热重载分析

## 概述

本文档分析哪些配置可以热重载（运行时修改立即生效），哪些配置不可热重载（需要重启应用）。

## 配置来源分类

| 来源 | 文件 | 热重载策略 |
|------|------|-----------|
| `appsettings.json` | `Resources/appsettings.json` | 部分可热重载 |
| 人格配置文件 | `Resources/Personalities/{名称}_person.json` | 人格提示词可热重载（非整个 System Prompt） |
| SQLite 数据库 | `Resources/Data/mochibot.db` | 运行时可变，走 DatabaseService |

---

## 可热重载的配置

### AppSettings 中可热重载

| 配置项 | 说明 | 热重载影响范围 |
|--------|------|---------------|
| `UserName` | 用户名称 | 下次构建 System Prompt 时生效 |
| `EnableStructuredResponse` | 是否启用结构化响应 | 下次 LLM 调用时生效 |
| `MaxActionsPerResponse` | 单次最大动作数 | 下次执行 actions 时生效 |
| `EnableMidTermMemoryOnChat` | 对话时允许录入中期记忆 | 下次对话时生效 |
| `EnableLongTermRecall` | 对话时检索长期记忆 | 下次对话时生效 |
| `LogLevel` | 日志级别 | 立即生效 |
| `LogToFile` | 日志文件输出 | 立即生效 |
| `LogToConsole` | 日志控制台输出 | 立即生效 |

### ModuleSettings 中可热重载

| 配置项 | 说明 | 热重载影响范围 |
|--------|------|---------------|
| `ShortTermMemory_Capacity` | 短期记忆容量 | 下次添加消息时生效 |
| `ShortTermMemory_TrimThreshold` | 短期记忆裁剪阈值 | 下次溢出时生效 |
| `ShortTermMemory_OverflowStrategy` | 溢出策略 | 下次溢出时生效 |
| `MidTermMemory_MaxEntries` | 中期记忆最大条目 | 下次录入时生效 |
| `MidTermMemory_ImportanceThreshold` | 重要度阈值 | 下次评估时生效 |
| `MidTermMemory_KeywordScanInterval` | 关键词扫描间隔 | 下次定时任务触发时生效 |
| `LongTermMemory_PromotionInterval` | 晋升间隔 | 下次定时任务触发时生效 |
| `LongTermMemory_PromotionThreshold` | 晋升阈值 | 下次晋升时生效 |
| `AutoEvent_MurmurWeight` | 碎碎念权重 | 下次碎碎念事件时生效 |
| `MurmurTexts` | 碎碎念文本列表 | 下次使用内置文本时生效 |
| `ComplimentTemplates` | 夸奖文本列表 | 下次 fallback 时生效 |

### ProviderConfig 中可热重载

| 配置项 | 说明 | 热重载影响范围 |
|--------|------|---------------|
| `ApiKey` | LLM API 密钥 | 通过重载事件通知各模块重建 LlmClient |
| `BaseUrl` | LLM API 地址 | 通过重载事件通知各模块重建 LlmClient |
| `ContextLimit` | 上下文限制 | 通过重载事件通知各模块更新 |

### 人格配置中可热重载

| 配置项 | 说明 | 热重载影响范围 |
|--------|------|---------------|
| 人格描述/子人格描述 | 人格提示词 | 下次构建 System Prompt 时生效（不是整个 System Prompt 重载） |

### 定时任务配置中可热重载

| 配置项 | 说明 | 热重载影响范围 |
|--------|------|---------------|
| `CronTasks` 列表 | 定时任务定义 | 需要重新调度定时器 |

---

## 不可热重载的配置

| 配置项 | 原因 |
|--------|------|
| `ActivePersonality` | 切换激活人格需要重新加载人格配置文件，属于重大状态变更 |

## 热重载实现方案

### 事件流

```
UI 发出配置更新事件 (EventCategory.ConfigUpdate)
    ↓
ConfigReader 订阅 ConfigUpdate 事件 → 更新内存缓存 → 持久化到 JSON
    ↓
ConfigReader 发出热重载事件 (EventCategory.ConfigChanged)
    ↓
其他模块（Agent、ShortTermMemory、LongMemory）订阅 ConfigChanged 事件
    ↓
各模块根据事件 Info 中的变更类型执行对应的热重载逻辑
```

### 各模块对配置变更的响应

| 模块 | 监听的变更 | 响应动作 |
|------|-----------|---------|
| ConfigReader | ConfigUpdate | 更新内存缓存 + 持久化 JSON + 发出 ConfigChanged |
| Agent | ConfigChanged (ProviderConfig) | 重建 LlmClient |
| Agent | ConfigChanged (人格配置) | 刷新人格描述缓存（下次 BuildSystemPrompt 时生效） |
| Agent | ConfigChanged (AppSettings) | 刷新相关设置 |
| ShortTermMemory | ConfigChanged (ProviderConfig) | 重建 LlmClient |
| ShortTermMemory | ConfigChanged (MaxMessages) | 调整 Capacity |
| LongMemory | ConfigChanged (ProviderConfig) | 重建 LlmClient |

### 事件分类

```csharp
// EventTypes.cs 新增
EventCategory.ConfigUpdate,   // UI → ConfigReader：配置更新请求
EventCategory.ConfigChanged   // ConfigReader → 各模块：配置已变更，请热重载
```

### 事件 Info 格式

```json
// ConfigUpdate 事件 Info
{
  "type": "appsettings",           // 或 "personality"
  "changes": {
    "AppSettings.UserName": "新主人",
    "ModuleSettings.ShortTermMemory_Capacity": 100
  }
}

// ConfigChanged 事件 Info
{
  "changedItems": ["ProviderConfig", "AppSettings.UserName", "ModuleSettings.ShortTermMemory_Capacity"],
  "providerName": "LocalLMStudio"  // 仅当 ProviderConfig 变更时
}
```

### 设计要点

1. **UI 缓存机制**：UI 修改配置时暂存在 UI 层，只有点击"保存"按钮才发出 ConfigUpdate 事件
2. **ConfigReader 作为中间人**：收到 ConfigUpdate → 更新缓存 + 持久化 → 发出 ConfigChanged
3. **事件驱动**：所有模块间通信都通过 EventDispatcher，保持架构一致性
4. **人格提示词热重载**：System Prompt 模板固定，只有人格描述部分从 ConfigReader 动态读取，变更后下次构建自动生效
5. **ProviderConfig 热重载**：通过 ConfigChanged 事件通知各模块自行重建 LlmClient 实例
