# 接口调用关系与协作图

## 完整模块依赖关系

服务层以 **Agent 核心协调层** 为中心，Agent 通过事件调度器接收事件，统一调度以下模块：

- **ConfigReader**: 配置读取器（统一管理所有配置读取）
- **LlmClient**: LLM API调用封装
- **PromptFormatter**: Prompt构建
- **ShortTermMemory**: 短期记忆（集成到Agent）
- **LongMemory**: 长期记忆（中期+长期合并）
- **ToolManager**: 工具管理器（统一调度所有工具）
- **AgentMoodTracker**: 情绪管理器（集成到Agent）
- **ICharacterRenderer**: 角色动画渲染接口
- **DatabaseService**: 数据库持久化
- **IJsPluginLoader**: JS插件加载器
- **IMcpService**: MCP服务管理

UI 层 (Form1) 和 AutoEventService 通过事件调度器与 Agent 交互，不直接调用其他服务模块。

## 接口调用矩阵

| 调用方 | 被调用方 | 说明 |
| Form1 (UI) | EventDispatcher | 发布用户交互事件 |
| Form1 (UI) | DatabaseService | 直接读取配置（如加载设置） |
| Form1 (UI) | ICharacterRenderer | 直接控制动画播放（如双击拥抱） |
| EventDispatcher | Agent | 分发事件给 Agent 处理 |
| AutoEventService | EventDispatcher | 发布系统自动事件 |
| Agent | ConfigReader | 获取应用级配置、人格配置、模块参数 |
| Agent | LlmClient | 对话模式和函数模式都通过 LlmClient |
| Agent | PromptFormatter | 构建对话 prompt |
| Agent | ShortTermMemory | 读写短期记忆 |
| Agent | LongMemory | 检索和录入长期记忆 |
| Agent | ToolManager | 执行工具调用 |
| Agent | AgentMoodTracker | 切换情绪 |
| Agent | ICharacterRenderer | 播放动画 |
| Agent | DatabaseService | 持久化数据 |
| LlmClient | ConfigReader | 获取提供商配置（含 ContextLimit）和模型列表 |
| ToolManager | AgentMoodTracker | 工具执行后更新情绪 |
| ToolManager | IJsPluginLoader | 执行JS插件工具 |
| ToolManager | IMcpService | 执行MCP工具 |
| ToolManager | ICharacterRenderer | 播放动画 |
| LongMemory | LlmClient | 函数模式：评估重要度、提取关键词 |

**关键变化**：

- Form1 不再直接调用 LlmClient/Memory/ToolService 等，全部通过事件调度器 → Agent 统一调度
- AutoEventService 不再直接调用 LlmClient，而是通过事件调度器发布事件
- 原 ToolService 拆分为 ToolManager（调度层）+ 各工具执行器
- 原 MidTermMemory 和 LongTermMemory 合并为 LongMemory
- 原 AgentMoodTracker 和 ShortTermMemory 集成到 Agent 中

## 完整交互流程

### 1. 应用启动流程

1. Program.Main() 启动
2. ConfigReader.Initialize("appsettings.json") 初始化配置读取器
3. Form1 构造函数初始化各模块（通过 ConfigReader 获取配置）：
   - 初始化 EventDispatcher
   - 初始化 LlmClient
   - 初始化 Agent（含 AgentMoodTracker、ShortTermMemory、LongMemory）
   - 初始化 ToolManager
   - 初始化 DatabaseService
   - 初始化 AutoEventService（启动定时任务）
   - 初始化 JsPluginLoader（加载所有JS插件）
   - 初始化 McpService（连接MCP服务器）
   - 初始化 CharacterRenderer（加载角色动画资源）
4. Agent 订阅 EventDispatcher 的事件
5. AutoEventService 启动，开始发布系统自动事件

### 2. 用户发送消息流程

1. Form1 用户输入文本
2. Form1 调用 EventDispatcher.PublishAsync(UserMessage, "chat", 文本)
3. Agent 接收事件，短期记忆.AddMessage("user", 文本)
4. Agent 构建完整 Prompt（含长期记忆检索）
5. Agent 调用 LlmClient.SendChatAsync() 对话模式
6. Agent 解析 LLM 响应：提取 reply 文本 + 解析 actions 数组
7. Agent 遍历执行 actions：
   - tool_call → ToolManager.ExecuteToolAsync()
   - mood_change → AgentMoodTracker.SetMood()
   - animation → ICharacterRenderer.PlayAnimation()
   - midterm_memory → LongMemory.AddEntryAsync()
8. Agent 短期记忆.AddMessage("assistant", reply)
9. Agent 检查短期记忆是否溢出，溢出时录入 LongMemory
10. Agent 更新情绪
11. Agent 返回 reply 给 Form1 显示

### 3. 用户双击头像（拥抱功能）

1. Form1 双击事件触发
2. ICharacterRenderer.PlayAnimation("hug") 播放拥抱动画
3. Form1 发布 UserInteraction 事件（EventType: "hug"）
4. Agent 接收事件，处理拥抱逻辑

### 4. 碎碎念自动触发流程

1. AutoEventService 定时器到达
2. AutoEventService 发布 SystemAuto 事件（EventType: "murmur"）
3. Agent 接收事件，根据 EventType 构建对应 Prompt
4. Agent 调用 LlmClient.SendChatAsync() 对话模式
5. Agent 解析 LLM 响应，执行 actions
6. Agent 返回 reply → UI 显示气泡

### 5. 用户点击"摸摸她"流程

1. Form1 用户点击"摸摸她"
2. Form1 发布 UserInteraction 事件（EventType: "pet"）
3. Agent 接收事件
4. Agent 判断 EventType == "pet"
5. 基本反应：情绪切换为 Touched，播放 pet_head 动画
6. 概率触发 LLM 处理
7. 如果触发：LLM 生成回复 + actions
8. ToolManager 执行工具
9. 回复用户

### 6. 工具执行流程

1. Agent 解析 LLM 响应中的 actions
2. Agent 调用 ToolManager.ExecuteToolAsync(toolName, parameters)
3. ToolManager 根据工具类型路由：
   - 基础工具 → 内置执行逻辑
   - 心情特色工具 → 内置执行逻辑（含情绪切换）
   - MCP工具 → IMcpService.CallToolAsync()
   - JS注册工具 → IJsPluginLoader.ExecutePluginAsync()
4. 执行结果返回 Agent

## 数据流方向

```
用户输入 → Form1 (UI)
    → EventDispatcher (事件调度层)
    → Agent (核心协调层)
        → LlmClient / ToolManager / LongMemory / AgentMoodTracker (服务层)
        → ConfigReader / DatabaseService / ICharacterRenderer (基础设施层)
    → 回复用户
```

## 关键设计原则

1. **事件驱动架构**: 所有交互通过事件调度器分发，解耦事件源和事件处理器
2. **Agent 是唯一入口**: Agent 处理所有事件，协调各模块
3. **工具管理器统一调度**: 基础工具、心情工具、MCP工具、JS插件统一由 ToolManager 管理
4. **面向接口编程**: 所有模块通过接口交互，便于单元测试和模块替换
5. **单一职责**: 每个模块只负责一个领域的功能
6. **依赖注入**: 模块间通过构造函数注入依赖，便于管理和测试
7. **异步非阻塞**: 所有I/O操作（LLM调用、文件读写、API请求）使用 async/await
8. **记忆模块集成化**: 短期记忆集成到Agent中，中期和长期记忆合并为 LongMemory
