# 接口调用关系与协作图

## 完整模块依赖关系

服务层以 **Agent 核心协调层** 为中心，Agent 统一调度以下模块：

- **ConfigReader**: 配置读取器（统一管理所有配置读取）
- **LlmClient**: LLM API调用封装
- **PromptFormatter**: Prompt构建
- **ShortTermMemory**: 短期记忆
- **MidTermMemory**: 中期记忆
- **LongTermMemory**: 长期记忆
- **ToolService**: 工具功能服务
- **AgentMoodTracker**: 情绪管理器
- **CharacterRenderer**: 角色动画渲染（GIF/PNG图集）
- **DatabaseService**: 数据库持久化
- **JsPluginLoader**: JS插件加载器

UI 层 (Form1) 和 AutoEventService 只依赖 Agent，不直接调用其他服务模块。

## 接口调用矩阵

| 调用方 | 被调用方 | 说明 |
| Form1 (UI) | Agent | 所有用户交互走 Agent 统一调度 |
| Form1 (UI) | DatabaseService | 直接读取配置（如加载设置） |
| Form1 (UI) | CharacterRenderer | 直接控制动画播放（如双击拥抱） |
| Agent | ConfigReader | 获取应用级配置、人格配置、模块参数 |
| Agent | LlmClient | 对话模式和函数模式都通过 LlmClient |
| Agent | PromptFormatter | 构建对话 prompt |
| Agent | ShortTermMemory | 读写短期记忆 |
| Agent | MidTermMemory | 录入中期记忆 |
| Agent | LongTermMemory | 检索长期记忆 |
| Agent | ToolService | 执行工具调用 |
| Agent | JsPluginLoader | 执行插件调用 |
| Agent | AgentMoodTracker | 切换情绪 |
| Agent | CharacterRenderer | 播放动画 |
| Agent | DatabaseService | 持久化数据 |
| LlmClient | ConfigReader | 获取提供商配置（含 ContextLimit）和模型列表 |
| AutoEventService | Agent | 自动事件触发后由 Agent 处理 |
| MidTermMemory | LlmClient | 函数模式：评估重要度 |
| LongTermMemory | LlmClient | 函数模式：提取关键词 |
| ToolService | AgentMoodTracker | 工具执行后更新情绪 |
| ToolService | JsPluginLoader | 工具可调用插件 |
| ToolService | CharacterRenderer | 工具可播放动画 |

**关键变化**：

- Form1 不再直接调用 LlmClient/Memory/ToolService 等，全部通过 Agent 统一调度
- AutoEventService 不再直接调用 LlmClient，而是触发 Agent.ProcessAutoEventAsync()
- MidMem/LongMem 在函数模式下直接调用 LlmClient（纯LLM调用，不走人格层）

## 完整交互流程

### 1. 应用启动流程

1. Program.Main() 启动
2. ConfigReader.Initialize("appsettings.json") 初始化配置读取器（加载提供商配置、应用级配置、模块参数、人格配置）
3. Form1 构造函数初始化各模块（通过 ConfigReader 获取配置）：
   - 初始化 LlmClient（通过 ConfigReader 获取提供商配置和 ContextLimit）
   - 初始化 AgentMoodTracker
   - 初始化 ShortTermMemory（从 DatabaseService 加载历史记录）
   - 初始化 MidTermMemory
   - 初始化 LongTermMemory
   - 初始化 DatabaseService（加载用户配置）
   - 初始化 PromptFormatter
   - 初始化 ToolService
   - 初始化 AutoEventService（启动定时任务）
   - 初始化 JsPluginLoader（加载所有JS插件）
   - 初始化 CharacterRenderer（加载角色动画资源）

### 2. 用户发送消息流程（对话模式）

1. Form1 调用 Agent.ProcessUserInputAsync(userMessage)
2. Agent 内部：短期记忆.AddMessage("user", userMessage)
3. Agent 构建完整 Prompt：PromptFormatter 构建 system prompt（含长期记忆检索）+ user context（含短期/中期记忆）+ Agent 指令
4. Agent 调用 LlmClient.SendChatAsync(messages) 对话模式
5. Agent 解析 LLM 响应：提取 reply 文本 + 解析 actions 数组
6. Agent 遍历执行 actions：tool_call → ToolService、plugin_call → JsPluginLoader、mood_change → AgentMoodTracker、midterm_memory → MidTermMemory、animation → CharacterRenderer
7. Agent 短期记忆.AddMessage("assistant", reply)
8. Agent 检查短期记忆是否溢出，如果溢出则按概率抽取，用函数模式 EvaluateImportanceAsync() 评估重要度后录入 MidTermMemory
9. Agent 调用 AgentMoodTracker.UpdateMoodByEvent("Active")
10. Agent 返回 reply 给 Form1 显示

### 3. 用户双击头像（拥抱功能）

1. Form1 双击事件触发
2. CharacterRenderer.PlayAnimation("hug") 播放拥抱动画
3. Agent.ProcessUserInputAsync("(用户双击了头像)") 走 Agent 对话模式
4. LLM 识别为拥抱请求，返回拥抱回应，actions 包含 mood_change: happy

### 4. 碎碎念自动触发流程（对话模式）

1. AutoEventService 定时器到达，触发 OnMurmur 事件
2. Agent.ProcessAutoEventAsync("murmur", null) 被调用
3. Agent 根据 eventType 构建对应 Prompt（murmur/eye_rest/late_night）
4. Agent 注入 Agent 指令，调用 LlmClient.SendChatAsync() 对话模式
5. Agent 解析 LLM 响应，执行 actions（可切换情绪等）
6. Agent 短期记忆.AddMessage("assistant", reply)
7. Agent 返回 reply → UI 显示气泡

### 5. 用户点击"摸摸她"流程

1. Form1 调用 Agent.ProcessToolCallAsync("pet", "")
2. Agent 调用 ToolService.PetAsync()
3. ToolService 内部：CharacterRenderer.PlayAnimation("pet_head") + AgentMoodTracker.SetMood(Touched)
4. Agent 返回结果 → UI 显示回应

## 数据流方向

用户输入 → Form1 (UI) → Agent (服务层) → Model (数据层) → 事件驱动/API调用/文件读写

## 关键设计原则

1. **面向接口编程**：所有模块通过接口（Interface）交互，便于单元测试和模块替换
2. **事件驱动**：UI层通过订阅事件响应服务层变化，避免紧耦合
3. **单一职责**：每个模块只负责一个领域的功能
4. **依赖注入**：模块间通过构造函数注入依赖，便于管理和测试
5. **异步非阻塞**：所有I/O操作（LLM调用、文件读写、API请求）使用 async/await
