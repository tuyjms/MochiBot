## 什么是上帝类

上帝类（God Class）是指承担了过多职责的类，违反了单一职责原则（SRP）。特征包括：
- 字段数量远超同类
- 方法数量过多，涵盖多个不相关的关注点
- 修改任何一个维度都可能波及其他逻辑
- 难以进行单元测试（依赖过多、状态复杂）

### 依赖关系

```
MainAgent
├── IEventDispatcher      （事件发布/订阅）
├── IConfigReader          （配置读取）
├── IToolService           （工具执行）
├── MoodLogRepository      （情绪日志数据库）
├── LlmClient ×2           （对话模型 + 函数调用模型）
├── ShortTermMemory        （短期记忆）
├── LongMemory             （长期记忆）
├── ActionExecutor         （Action 执行）
└── PromptFormatter ×2     （Prompt 模板格式化）
```

### 建议拆分方向

| 新类 | 职责 | 从 MainAgent 迁移的内容 |

| `ConfigHotReloader` | 配置热重载 | `OnConfigChanged`, LlmClient/记忆模块重建逻辑 |

## 重构优先级建议

```
Phase 1: MainAgent 拆分（影响最大）
  ├── 提取 MoodManager（情绪逻辑独立，与 Agent 核心流程正交）
  ├── 提取 MemoryCoordinator（记忆管理独立，含维护定时器）
  └── 提取 EventQueueProcessor（队列+状态机独立）

Phase 2: MainWindow 拆分
  ├── 提取 PassthroughManager（Win32 P/Invoke 隔离）
  └── 提取 DisplayModeManager（GIF/VRM 模式切换）

Phase 3: 基础设施层
  ├── ConfigReader 日志独立
  └── EventDispatcher 的 CronScheduler 独立
```
