# UI 改动规划

## 一、移除最小化按钮 + 托盘随启动

### 1.1 移除最小化按钮

**改动文件**：
- `Src/UI/MainWindow.xaml` — 删除 🔽 最小化按钮的 `<Border>` + `<Button>` 节点
- `Src/UI/MainWindow.xaml.cs` — 删除 `MinimizeButton_Click` 方法

### 1.2 托盘图标随应用启动

**现状**：`TrayIcon` 在 `OnSourceInitialized` 中创建但不显示，仅在用户点击最小化按钮时 `Show()`

**目标**：应用启动时托盘图标即刻可见，始终驻留

**改动**（`MainWindow.xaml.cs`）：
- `OnSourceInitialized` 中创建 `TrayIcon` 后立即调用 `Show()`
- `RestoreFromTray` 不再 `Hide()` 托盘（始终显示）
- `OnClosing` 中 `Dispose` 托盘（正常退出时清理）

**托盘交互逻辑**：
| 操作 | 行为 |
|---|---|
| 左键单击 | 切换主窗口 显示/隐藏 |
| 右键 | 弹出菜单（穿透 / 设置 / 聊天） |

## 二、工具栏自动浮现（auto-hide）

### 2.1 交互设计

- 工具栏默认**隐藏**
- 鼠标悬停在**窗口底部区域**（底部 20px）时，工具栏**淡入**浮现
- 鼠标离开工具栏区域后，工具栏**淡出**隐藏（延迟 300ms 防抖）
- 右键切换保留作为备用入口

### 2.2 实现方案

**改动文件**：`MainWindow.xaml` + `MainWindow.xaml.cs`

**XAML 改动**：
- 给 `toolbarPanel` 加 `Opacity="0"` + `IsHitTestVisible="False"` 默认状态
- 添加 `MouseEnter` / `MouseLeave` 事件到主窗口或底部触发区域

**代码改动**：
- 在 `characterContainer` 或主窗口底部放一个透明的触发 `Border`（高 20px，DockPanel.Dock="Bottom"）
- `Border.MouseEnter` → 淡入 toolbarPanel（`DoubleAnimation` Opacity 0→1，150ms），设 `IsHitTestVisible=True`
- `toolbarPanel.MouseLeave` → 延迟 300ms 后淡出（Opacity 1→0），设 `IsHitTestVisible=False`
- 删除原有的 `Window_MouseRightButtonDown` + `ToggleToolbar` 逻辑

**动画**：使用 WPF `Storyboard` + `DoubleAnimation`，无需额外依赖

## 三、气泡消息自动消失

### 3.1 交互设计

- 文本有时会溢出气泡
- 气泡显示后根据文本长度**自动计算停留时间**：`基础2秒 + 每50字加1秒`，上限 8 秒
- 停留时间结束后**淡出消失**（Opacity 动画 300ms）
- 点击气泡仍可打开聊天窗口（点击时取消自动消失计时器）

### 3.2 实现方案

**改动文件**：`MainWindow.xaml.cs`

**代码改动**：
- `ShowBubble()` 中：
  - 计算停留时长：`var duration = TimeSpan.FromSeconds(Math.Min(2 + text.Length / 50.0, 8));`
  - 启动 `DispatcherTimer`，到期后触发淡出动画
  - 淡出完成后 `chatBubble.Visibility = Collapsed`
- `Bubble_Click` 中：停止自动消失计时器，再执行原有逻辑
- `HideBubble()` 中：停止计时器
- 淡出动画：`DoubleAnimation` Opacity 1→0，300ms，完成后设 `Visibility.Collapsed`

## 四、SVG 矢量图标替换 Emoji

### 4.1 目标

用 WPF `Path` 矢量图形替换工具栏按钮的 Emoji（⚙️💬📌），保证跨系统/DPI 一致渲染

### 4.2 图标选型

使用 **Segoe Fluent Icons** 字体或内嵌 `Path` 数据（Material Design 风格）：

| 按钮 | 图标 | Path 数据来源 |
|---|---|---|
| 设置 ⚙️ | Settings Gear | Segoe Fluent Icons `` 或 MDI `cog` |
| 聊天 💬 | Chat | Segoe Fluent Icons `` 或 MDI `message-text` |
| 穿透 📌 | Pin | Segoe Fluent Icons `` 或 MDI `pin` |

### 4.3 实现方案

**改动文件**：`MainWindow.xaml` + `TrayIcon.cs`（穿透按钮）

**XAML 改动**（以设置按钮为例）：
```xml
<!-- 替换前 -->
<Button Content="⚙️" FontSize="16" .../>

<!-- 替换后 -->
<Button ToolTip="设置" ...>
    <Path Data="M..." Fill="#FF333333" Width="18" Height="18"
          Stretch="Uniform" HorizontalAlignment="Center" VerticalAlignment="Center"/>
</Button>
```

**样式统一**：
- 所有图标统一 `Width="18" Height="18" Stretch="Uniform"`
- 默认填充 `#FF333333`，hover 时通过 `Trigger` 变为 `#FF6B5CE7`（主题色）
- 加 `ToolTip` 文字提示

**穿透按钮**：穿透按钮在 `ShowPassthroughWindow()` 中代码创建，同样替换为 `Path` 控件

## 五、设置窗口改为非模态

### 5.1 什么是模态 vs 非模态

| | 模态（当前） | 非模态（目标） |
|---|---|---|
| 打开方式 | `ShowDialog()` | `Show()` |
| 打开后能否操作其他窗口 | ❌ 不能，其他窗口全部锁死 | ✅ 可以，各窗口独立 |
| 典型场景 | 必须先处理完才能继续 | 边调边看效果 |

### 5.2 为什么桌宠适合非模态

- 调整人格/模型参数时，能**实时看到桌宠的表情和行为变化**
- 可以一边改设置一边在聊天窗口测试对话效果
- 设置窗口可以拖到屏幕角落，不遮挡桌宠

### 5.3 实现方案

**改动文件**：`MainWindow.xaml.cs`

**代码改动**：
```csharp
// 改前
private void SettingsButton_Click(object sender, RoutedEventArgs e)
{
    var settingsWindow = new SettingsWindow(_configReader, _eventDispatcher, this, _userConfigRepository);
    settingsWindow.ShowDialog();  // 模态，阻塞
}

// 改后
private Window? _settingsWindow;  // 字段，防止重复打开

private void SettingsButton_Click(object sender, RoutedEventArgs e)
{
    if (_settingsWindow != null)
    {
        _settingsWindow.Activate();  // 已打开则激活
        return;
    }
    _settingsWindow = new SettingsWindow(_configReader, _eventDispatcher, this, _userConfigRepository);
    _settingsWindow.Closed += (_, _) => _settingsWindow = null;  // 关闭时清理引用
    _settingsWindow.Show();  // 非模态
}
```

**注意事项**：
- `SettingsWindow` 需要设置 `Owner = this`，这样它会跟随主窗口显示/隐藏
- 添加防重复打开逻辑（检查 `_settingsWindow != null`）
- `Closed` 事件清理引用，允许再次打开
