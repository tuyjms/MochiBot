## 一、设置窗口 UI（SettingsWindow）— 待完善

当前 `Src/UI/SettingsWindow.xaml` 只有基础设置（用户名、透明度、碎碎念开关/间隔），以下功能待实现：

### 1️⃣ 人格管理

涉及文件：`Resources/Personalities/` + `Resources/appsettings.json`

- **人格列表**：扫描 `Resources/Personalities/*_person.json`，显示可选人格列表
- **新增人格**：表单输入名称（合法性检查：只允许中文、英文、数字、下划线，不能以数字开头）、描述、模型配置，自动创建 `{名称}_person.json`
- **删除人格**：确认后删除对应文件（禁止删除当前激活人格）
- **切换激活人格**：下拉菜单选择 → 写入 `AppSettings.ActivePersonality` → 保存 → 触发热重载（`ConfigChanged` 事件 → Agent 刷新人格缓存）

### 2️⃣ 子人格管理

涉及文件：`Resources/Personalities/*_person.json`，模型见 `Src/Core/Config/Models/PersonalityConfig.cs`

- **子人格列表**：显示当前人格下的所有子人格（`personalities[]`），含名称、描述、权重
- **新增子人格**：添加名称、描述、权重，子人格可为空（空名称视为占位符）
- **删除子人格**：确认后从数组中移除
- **权重合法性检查**：提示所有权重之和必须为 100
  - 权重和不为 100 时，人格切换机制自动禁用（参见 `Agent.cs:SelectSubPersonalityByWeight`），使用第一个子人格作为默认
  - 只有所有权重和恰好为 100 时，LLM 响应时才会按概率随机切换子人格

### 3️⃣ Cron 表达式辅助

- **下拉菜单预设**：
  - 每 N 分钟：`*/5 * * * *`、`*/10 * * * *`、`*/25 * * * *`、`*/30 * * * *`
  - 每小时：`0 * * * *`
  - 每天固定时间：`0 9 * * *`、`0 23 * * *`
  - "自定义"：允许手动输入
- **说明提示**（ToolTip）：5 字段格式说明（分 时 日 月 周）

### 4️⃣ 内置任务配置

对应 `Resources/appsettings.json` 中的 `CronTasks[]` 数组，当前已有 4 个内置任务：

| 任务 | 字段 | 控件类型 |
|------|------|----------|
| 碎碎念（builtin:murmur） | 启用开关 + 权重滑动条(0-100) | CheckBox + Slider |
| 用眼提醒（builtin:eye_rest） | 启用开关 + 阈值分钟数输入 | CheckBox + TextBox |
| 深夜关怀（builtin:late_night） | 启用开关 + 偏移范围滑动条(-30~30) | CheckBox + Slider（双值） |
| 空闲检测（builtin:idle_check） | 启用开关 + 阈值分钟数输入 | CheckBox + TextBox |

- 保存后调用 `EventDispatcher.SetTaskEnabled(taskId, enabled)` 实时生效
- 参数变更需重复写入 `appsettings.json`，调用 `ConfigReader.Reload()` 刷新

### 5️⃣ 配置热重载链路

当前链路已打通：
```
SettingsWindow 保存
  → 写入 appsettings.json
  → ConfigReader.Reload()
  → 发布 EventCategory.ConfigChanged 事件
  → Agent 订阅 OnConfigChanged，刷新 ProviderConfig / PersonalityConfig / MaxMessages
```

扩展时注意：新增配置项需在 `SettingsWindow.SaveAppSettingsAsync` 中添加对应的字段序列化（当前是手动逐字段写入 JSON，容易遗漏）。

```

  → MainWindow 订阅收到 "vrm:dance" → CharacterRenderer 找不到 → 静默跳过（安全）
```

## 十、技术债 & 潜在问题

1. **AutoEventService 冗余**：`Src/Services/AutoEventService.cs` 和 `Src/Services/IAutoEventService.cs` 中的 Cron 匹配逻辑与 `EventDispatcher` 重复，且已不被引用（`Main.cs:Initialize` 只使用 `EventDispatcher`），建议清理
2. **DatabaseServiceTests 编译失败**：`MochiBot.Tests/Services/DatabaseServiceTests.cs` 引用了 `DatabaseService` 上已被重构到 Repository 类的方法（`SaveConfigAsync`/`LoadConfigAsync`/`SaveChatHistoryAsync`/`LoadChatHistoryAsync`/`LogMoodChangeAsync`/`GetMoodLogAsync`），导致 20 个 CS1061 错误，整个测试项目无法构建
3. **LlmClient 硬编码超时**：OpenAI.Client 默认超时 100 秒，应改为从 `ProviderConfig` 读取
4. **空 catch 模式**：多处使用 `try { } catch { }`（如 `EventDispatcher.Publish`、`BuiltinTaskHandler.OnSystemAutoEvent`），可能掩盖真实问题
5. **线程安全**：
   - `EventDispatcher.CheckCronTasks` 在 Timer 线程中同步调用 `Publish`，而 `Publish` 会同步调用订阅者（含 Agent 的 LLM 调用），可能阻塞 Timer
   - `BuiltinTaskHandler._isHandling` 在 `OnSystemAutoEvent` 中防止重入，但多个不同事件的发布仍可能并发
6. **SettingsWindow 序列化脆弱**：`SaveAppSettingsAsync` 手动构建 JSON，新增字段需要同步修改此方法，容易遗漏
7. **配置缺失**：`AppSettings.UserName` 在模型中有定义（参见 `Src/Core/Config/Models/AppSettings.cs`），但 `appsettings.json` 中未包含，需要在两个地方保持同步
