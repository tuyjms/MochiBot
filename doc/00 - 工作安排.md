## 协作须知

请先阅读 `doc/00 - 写给viber的话.md`，了解本项目的基本协作规范：

- **Git 提交格式**：`影响程度词：一句话描述`（如 `功能改动：添加天气查询模块`）
- **互不干涉原则**：提前说明要施工的模块，不得修改负责范围外的模块
- **配置管理规范**：所有配置项必须通过 **ConfigReader** 统一管理，禁止硬编码
- **日志规范**：所有模块必须通过 ConfigReader 的 Logger 打印日志，禁止 `Console.WriteLine`
- **新增配置项流程**：发起协商 → 注册到配置读取器文档 → 实现代码 → 更新文档

## 一、设置窗口 UI（SettingsWindow）— 框架已完成，内容待填充

`0478c35` 已改造为 TabControl + 多目标 Save 分发。以下子任务待完成：

### 1️⃣ 人格管理

涉及文件：`Resources/Personalities/` + `Resources/appsettings.json`

- **人格列表**：扫描 `Resources/Personalities/*_person.json`，显示可选人格列表
- **新增人格**：表单输入名称（合法性检查：只允许中文、英文、数字、下划线，不能以数字开头）、描述、模型配置，自动创建 `{名称}_person.json`
- **删除人格**：确认后删除对应文件（禁止删除当前激活人格）
- **切换激活人格**：下拉菜单选择 → 写入 `AppSettings.ActivePersonality` → 保存 → 触发热重载（`ConfigChanged` 事件 → Agent 刷新人格缓存）

### 2️⃣ 子人格管理

涉及文件：`Resources/Personalities/*_person.json`，模型见 `Src/Core/Config/Models/PersonalityConfig.cs`

- **子人格列表**：显示当前人格下的所有子人格（`personalities[]`），含名称、描述、权重
- **新增子人格**：添加名称、描述、权重，子人格可为空（空名称视为占位符）
- **删除子人格**：确认后从数组中移除
- **权重合法性检查**：提示所有权重之和必须为 100
  - 权重和不为 100 时，人格切换机制自动禁用（参见 `Agent.cs:SelectSubPersonalityByWeight`），使用第一个子人格作为默认
  - 只有所有权重和恰好为 100 时，LLM 响应时才会按概率随机切换子人格

### 3️⃣ Cron 表达式辅助

- **下拉菜单预设**：
  - 每 N 分钟：`*/5 * * * *`、`*/10 * * * *`、`*/25 * * * *`、`*/30 * * * *`
  - 每小时：`0 * * * *`
  - 每天固定时间：`0 9 * * *`、`0 23 * * *`
  - "自定义"：允许手动输入
- **说明提示**（ToolTip）：5 字段格式说明（分 时 日 月 周）

### 4️⃣ 内置任务配置

对应 `Resources/appsettings.json` 中的 `CronTasks[]` 数组，当前已有 4 个内置任务：

| 任务 | 字段 | 控件类型 |
|------|------|----------|
| 碎碎念（builtin:murmur） | 启用开关 + 权重滑动条(0-100) | CheckBox + Slider |
| 用眼提醒（builtin:eye_rest） | 启用开关 + 阈值分钟数输入 | CheckBox + TextBox |
| 深夜关怀（builtin:late_night） | 启用开关 + 偏移范围滑动条(-30~30) | CheckBox + Slider（双值） |
| 空闲检测（builtin:idle_check） | 启用开关 + 阈值分钟数输入 | CheckBox + TextBox |

- 保存后调用 `EventDispatcher.SetTaskEnabled(taskId, enabled)` 实时生效
- 参数变更需重复写入 `appsettings.json`，调用 `ConfigReader.Reload()` 刷新

### 5️⃣ 配置热重载链路

`0478c35` 已完成。链路：`SettingsWindow 保存 → 多目标分发(appsettings/DB/Providers/ModuleSettings/Personality) → ConfigReader.Reload() → ConfigChanged 事件 → Agent 热重载`。新增配置项需在对应 Save 方法中添加字段序列化。

## 九、VRM 3D 动作接入 Agent 工具系统 — 查看器已完成，工具接入待实现

**目标**：让 LLM Agent 能通过 `play_motion` 工具调用，驱动 VrmViewerWindow 中的 VRM 3D 模型播放 `.vrma` 动作文件。

### 整体数据流

```
LLM 调用 play_motion(motion_name:"dance")
  → ActionExecutor → ToolService.ExecuteToolAsync → 返回 animation:"vrm:dance"
  → _onAnimation 回调 → EventDispatcher.MoodChange { animation:"vrm:dance" }
  → VrmViewerWindow 订阅过滤 "vrm:" 前缀 → ExecuteScriptAsync → JS 加载播放
  → MainWindow 订阅收到 "vrm:dance" → CharacterRenderer 找不到 → 静默跳过（安全）
```

- [x] `VrmViewerWindow`：WebView2 查看器窗口，App.xaml.cs 集成入口
- [x] `MainWindow`：VRM 查看器按钮
- [x] `Resources/Viewer/three-vrm-animation.module.js`：动画库已部署

## 十、技术债 & 潜在问题

1. **空 catch 模式**：多处 `try { } catch { }`（EventDispatcher.Publish、BuiltinTaskHandler 等），可能掩盖真实问题
2. **线程安全**：`EventDispatcher.CheckCronTasks` 在 Timer 线程同步调用 `Publish`，可能阻塞 Timer；`BuiltinTaskHandler._isHandling` 多事件并发问题
3. **XAML 硬编码**：`ChatWindow.xaml` 中 `Title="小琪"` 和 `Text="小琪"` 是设计时默认值，可改为数据绑定
