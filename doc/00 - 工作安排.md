# 工作安排

## 协作须知

请先阅读 `doc/00 - 写给viber的话.md`，了解本项目的基本协作规范：

- **Git 提交格式**：`影响程度词：一句话描述`（如 `功能改动：添加天气查询模块`）
- **互不干涉原则**：提前说明要施工的模块，不得修改负责范围外的模块
- **配置管理规范**：所有配置项必须通过 **ConfigReader** 统一管理，禁止硬编码
- **日志规范**：所有模块必须通过 ConfigReader 的 Logger 打印日志，禁止 `Console.WriteLine`
- **新增配置项流程**：发起协商 → 注册到配置读取器文档 → 实现代码 → 更新文档

## 八、VRM 3D 动作系统 — 事件驱动已完成

**目标**：VRM 模型表情由**心情切换事件**和 **Agent 状态机**自动驱动，使用 VRM 模型**自带的默认表情预设**（VRMExpressionManager API），暂不引入外部 `.vrma` 文件。

### 已完成

- [x] `vrm-viewer.html`：Three.js + @pixiv/three-vrm 渲染 VRM 模型，支持 OrbitControls 和 idle 动画（`db4a2df`）
- [x] `VrmViewerWindow`：WebView2 查看器窗口，App.xaml.cs 集成入口（`db4a2df`）
- [x] **事件驱动表情系统**：
  - 事件层：`EventCategory.ModuleState` 新增，`EventDispatcher.UpdateModuleState()` 自动发布状态变更事件
  - JS API：`window.setExpression(name, weight)` / `window.resetExpressions()` / `window.setLookAt(x, y)`
  - C# 通道：`VrmViewerWindow` 订阅 `MoodChange` + `ModuleState` 事件，通过 `PostWebMessageAsJson` 转发给 JS
  - 状态效果：`thinking→relaxed+视线偏下`、`error→surprised`、`idle→reset`

### 表情映射表

**心情 → VRM 表情**（`EventCategory.MoodChange` 驱动）：

| AgentMood | VRM expression | 说明 |
|-----------|----------------|------|
| `happy` | `happy` | 开心表情 |
| `sad` | `sad` | 难过表情 |
| `angry` | `angry` | 生气表情 |
| `sleepy` | `relaxed` | 放松/困倦 |
| `touched` | `happy` | 感动 → 开心 |
| `teasing` | `happy` | 调皮 → 开心 |
| `surprised` | `surprised` | 惊讶表情 |
| `neutral` | reset | 全部归零，恢复自动循环 |

**Agent 状态 → VRM 效果**（`EventCategory.ModuleState` 驱动）：

| Agent 状态 | VRM 效果 | 说明 |
|------------|----------|------|
| `idle` | reset | 恢复自动表情循环 |
| `thinking` | `relaxed` + 视线偏下 | 模拟"深思" |
| `error` | `surprised` | 异常时的惊讶反应 |
| `reloading` | reset | 热重载时恢复默认 |

## 九、技术债 & 潜在问题

1. **空 catch 模式**：多处 `try { } catch { }`（EventDispatcher.Publish、BuiltinTaskHandler 等），可能掩盖真实问题
2. **线程安全**：`EventDispatcher.CheckCronTasks` 在 Timer 线程同步调用 `Publish`，可能阻塞 Timer；`BuiltinTaskHandler._isHandling` 多事件并发问题
3. **XAML 硬编码**：`ChatWindow.xaml` 中 `Title="小琪"` 和 `Text="小琪"` 是设计时默认值，可改为数据绑定
