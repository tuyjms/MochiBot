# 长期记忆模块 (LongMemory)

## 模块概述

长期记忆模块是**中期记忆和长期记忆的合并**，统一管理所有需要长期保留的重要信息。采用 JSON 文件 + SQLite 双存储方案，每条记录包含关键词索引、事件描述、时间戳和重要度评分。

## 数据模型

```csharp
public class LongMemoryEntry
{
    public string Id { get; set; } = Guid.NewGuid().ToString();
    public string Keyword1 { get; set; } = string.Empty;  // 主词，通常是主语
    public string Keyword2 { get; set; } = string.Empty;  // 通常是谓语/动作
    public string Keyword3 { get; set; } = string.Empty;  // 通常是宾语/对象
    public string Description { get; set; } = string.Empty;
    public DateTime EventTimestamp { get; set; }
    public int Importance { get; set; }                    // 0-100
    public DateTime CreatedAt { get; set; } = DateTime.Now;
    public DateTime LastAccessedAt { get; set; } = DateTime.Now;
    public int AccessCount { get; set; } = 0;
    public string Source { get; set; } = string.Empty;     // Overflow / LLM / KeywordScan
}
```

## 核心接口

```csharp
public interface ILongMemory
{
    /// <summary>添加一条记录</summary>
    Task AddEntryAsync(LongMemoryEntry entry);

    /// <summary>批量添加记录</summary>
    Task AddEntriesAsync(IEnumerable<LongMemoryEntry> entries);

    /// <summary>按关键词搜索（用于对话时检索相关记忆）</summary>
    /// <param name="keywords">关键词列表</param>
    /// <param name="topN">返回前N条</param>
    Task<List<LongMemoryEntry>> SearchByKeywordsAsync(List<string> keywords, int topN = 5);

    /// <summary>按重要度筛选</summary>
    Task<List<LongMemoryEntry>> GetEntriesByImportanceAsync(int minImportance);

    /// <summary>按时间范围筛选</summary>
    Task<List<LongMemoryEntry>> GetEntriesByTimeRangeAsync(DateTime start, DateTime end);

    /// <summary>获取最近N条记录</summary>
    Task<List<LongMemoryEntry>> GetRecentEntriesAsync(int count = 20);

    /// <summary>根据ID获取记录</summary>
    Task<LongMemoryEntry?> GetEntryByIdAsync(string id);

    /// <summary>更新访问信息（用于LRU排序）</summary>
    Task UpdateAccessInfoAsync(string entryId);

    /// <summary>删除记录</summary>
    Task DeleteEntryAsync(string entryId);

    /// <summary>获取记录总数</summary>
    Task<int> GetCountAsync();

    /// <summary>清空所有记录</summary>
    Task ClearAsync();
}
```

## 关键词提取规则

### 优先规则：主谓宾提取

当事件描述是一个完整的句子时，优先提取主谓宾作为三个关键词。

例句："用户喜欢吃四川火锅" → 关键词1:"用户" 关键词2:"喜欢吃" 关键词3:"四川火锅"
例句："用户下周要去北京面试" → 关键词1:"用户" 关键词2:"去" 关键词3:"北京面试"

### 后备规则：无主谓宾时用3个关键词

当事件描述不是完整句子时，提取3个最重要的关键词。

描述："对猫毛过敏" → 关键词1:"猫" 关键词2:"过敏" 关键词3:"宠物"
描述："害怕打雷" → 关键词1:"害怕" 关键词2:"打雷" 关键词3:"天气"

### 关键词提取实现

由 LLM 负责从事件描述中提取关键词，调用专门的 prompt。

## 录入机制

### 机制A：短期记忆溢出触发

当短期记忆触发 Overflow 处理时，按概率抽取部分记忆录入长期记忆。

**触发条件**：短期记忆 `AddMessage()` 检测到 count > Capacity

**处理流程**：

1. 从即将被淘汰的旧记录中，按概率抽取 20%-50% 的记录
2. 对每条抽取的记录：提取关键信息，由LLM评估重要度(0-100)，录入长期记忆

**概率公式**：`P = min(0.5, 0.2 + 重要度因子 * 0.3)`

- 普通对话：20% 概率
- 包含关键词（喜欢/讨厌/想要/记得等）：30%-50% 概率

### 机制B：LLM主动调用

对话LLM在每次回复时，判断当前对话内容是否有值得记录的信息，主动调用 `AddEntryAsync()`。

**触发条件**：LLM在回复中检测到以下情况时主动录入：

- 用户提到个人偏好（"我喜欢吃辣"）
- 用户提到重要事件（"我下周要面试"）
- 用户表达强烈情绪（"我今天升职了！"）
- 用户提出长期需求（"帮我每天提醒我吃药"）

**实现方式**：在 LLM 的 system prompt 中加入指令，让 LLM 在回复时通过 actions 中的 `midterm_memory` 类型录入。

### 机制C：定期关键词扫描

定时任务从短期记忆中，通过出现频率最高的词查找相关聊天记录并录入。

**触发条件**：定时任务（默认每30分钟执行一次）

**处理流程**：

1. 扫描短期记忆中的所有消息，统计词频，找出TOP 10关键词
2. 用这些关键词反向查找相关的完整对话段落
3. 对找到的对话段落：去重、LLM评估重要度、录入长期记忆

**关键词过滤**：排除停用词（的、了、是、在、有、我、你等）

## 存储方案

### 双存储设计

长期记忆使用 JSON 文件 + SQLite 双存储：

- **JSON 文件**：用于快速读写和启动加载（`Resources/Data/long_memory.json`）
- **SQLite 数据库**：用于持久化存储和关键词搜索（`Resources/Data/long_memory.db`）

### SQLite 表结构

```sql
CREATE TABLE IF NOT EXISTS long_memory (
    id              TEXT PRIMARY KEY,
    keyword1        TEXT NOT NULL,
    keyword2        TEXT NOT NULL,
    keyword3        TEXT NOT NULL,
    description     TEXT NOT NULL,
    event_timestamp TEXT NOT NULL,
    importance      INTEGER NOT NULL DEFAULT 0,
    created_at      TEXT NOT NULL,
    last_accessed_at TEXT NOT NULL,
    access_count    INTEGER NOT NULL DEFAULT 0,
    source          TEXT NOT NULL DEFAULT ''
);

CREATE INDEX IF NOT EXISTS idx_keyword1 ON long_memory(keyword1);
CREATE INDEX IF NOT EXISTS idx_keyword2 ON long_memory(keyword2);
CREATE INDEX IF NOT EXISTS idx_keyword3 ON long_memory(keyword3);
CREATE INDEX IF NOT EXISTS idx_importance ON long_memory(importance DESC);
```

### 关键词搜索 SQL

```sql
SELECT DISTINCT *
FROM long_memory
WHERE (keyword1 IN ({keywords}) OR keyword2 IN ({keywords}) OR keyword3 IN ({keywords}))
ORDER BY importance DESC, last_accessed_at DESC
LIMIT {topN};
```

## 配置参数

| 参数 | 默认值 | 说明 |
| MaxEntries | 10000 | 最大条目数 |
| ImportanceThreshold | 30 | 最低录入重要度（低于此值不录入） |
| OverflowSampleRate | 0.3 | 爆上下文时的采样率 0.2-0.5 |
| KeywordScanInterval | 30 | 关键词扫描间隔（分钟） |
| TopKeywordsCount | 10 | 每次扫描提取的关键词数量 |
| SearchTopN | 5 | 关键词搜索返回前N条结果 |
| StoragePath | Resources/Data/long_memory.json | JSON存储路径 |
| DbPath | Resources/Data/long_memory.db | SQLite数据库路径 |

## 事件流

长期记忆有三个录入入口：短期记忆溢出触发、LLM主动调用、定时关键词扫描。三个入口最终都调用 `AddEntryAsync()` 录入。录入时先调用LLM提取关键词（函数模式），然后写入 SQLite 数据库和 JSON 文件。在对话时，Agent 通过 SearchByKeywordsAsync() 检索相关长期记忆注入上下文。

## 依赖关系

- **依赖**: `DatabaseService`（SQLite数据库操作）、`LlmClient`（关键词提取、重要度评估）、`ShortTermMemory`（读取短期记忆）
- **被依赖**: `Agent`（对话时检索相关记忆）

## 单元测试要求

| 测试用例 | 预期结果 |
|---------|----------|
| 添加单条记录 | AddEntryAsync 后 GetCountAsync == 1 |
| 批量添加记录 | AddEntriesAsync 后 GetCountAsync 等于添加数量 |
| 按关键词搜索 | SearchByKeywordsAsync(["猫"]) 返回包含"猫"的记录 |
| 按重要度筛选 | GetEntriesByImportanceAsync(70) 只返回重要度 >= 70 的记录 |
| 按时间范围筛选 | GetEntriesByTimeRangeAsync 只返回指定范围内的记录 |
| 更新访问信息 | UpdateAccessInfoAsync 后 LastAccessedAt 更新 |
| 删除记录 | DeleteEntryAsync 后 GetCountAsync 减少 |
| 清空所有记录 | ClearAsync 后 GetCountAsync == 0 |
| 获取最近 N 条 | GetRecentEntriesAsync(5) 返回 5 条 |
