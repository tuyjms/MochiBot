#长期记忆模块（原中期记忆和长期记忆模块）

## 录入机制

### 机制A：短期记忆溢出触发
当短期记忆容量满时，自动筛选重要信息录入。
*   **流程**：淘汰旧记录 → 按重要度概率抽样（20%-50%）→ LLM评估 → 入库。

### 机制B：定期关键词扫描
定时挖掘短期记忆中的高频话题。
*   **流程**：统计词频（排除停用词）→ 定位相关对话 → LLM评估 → 入库。

## 存储方案 (SQLite)

### 表结构

```sql
CREATE TABLE IF NOT EXISTS long_memory (
    id              TEXT PRIMARY KEY,
    keyword1        TEXT NOT NULL,
    keyword2        TEXT NOT NULL,
    keyword3        TEXT NOT NULL,
    description     TEXT NOT NULL,
    event_timestamp TEXT NOT NULL,
    importance      INTEGER NOT NULL DEFAULT 0,
    created_at      TEXT NOT NULL,
    last_accessed_at TEXT NOT NULL,
    access_count    INTEGER NOT NULL DEFAULT 0
);

-- 索引优化
CREATE INDEX IF NOT EXISTS idx_kw1 ON long_memory(keyword1);
CREATE INDEX IF NOT EXISTS idx_kw2 ON long_memory(keyword2);
CREATE INDEX IF NOT EXISTS idx_kw3 ON long_memory(keyword3);
```

## 配置参数

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `MaxEntries` | 10000 | 最大条目数 |
| `ImportanceThreshold` | 30 | 最低录入重要度 |
| `KeywordScanInterval` | 30 | 扫描间隔（分钟） |
| `SearchTopN` | 5 | 搜索返回条数 |

## 事件流

1.  **录入**：通过短期溢出、定时扫描或 Agent 主动调用 `AddEntryAsync()`。
2.  **检索**：对话时，Agent 调用 `SearchByKeywordsAsync()` 注入上下文。

## 依赖关系

*   **依赖**: `DatabaseService`（SQLite操作）、`LlmClient`（提取与评估）。
*   **被依赖**: `Agent`（上下文注入，Agent 在短期记忆溢出时调用 LongMemory 录入）。

## 单元测试

| 测试用例 | 预期结果 |
| :--- | :--- |
| 添加单条记录 | `AddEntryAsync` 后数据库计数 +1 |
| 关键词搜索 | `SearchByKeywordsAsync("猫")` 命中相关记录 |
| 重要度筛选 | 仅返回 `importance >= 70` 的记录 |
| 时间范围查询 | 仅返回指定时间段内的记录 |
| 更新访问时间 | 调用后 `last_accessed_at` 更新 |
| 删除与清空 | 数据库记录相应减少或归零 |
